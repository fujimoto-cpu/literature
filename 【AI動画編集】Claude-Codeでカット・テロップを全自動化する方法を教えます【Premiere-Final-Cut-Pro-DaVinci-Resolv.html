📝 要約（AI生成）

動画編集者である河村さんが、Claude Codeのスキル機能を使って動画編集（カット・テロップ生成・プラグイン開発）を自動化する具体的手順を解説する動画。普段10時間かかっていた1時間素材→25分動画の編集を、4〜5時間（半分以上）に短縮できた実例を共有している。

基本フローは次の通り：

  1. Premiere Proで素材を取り込み、画面収録と音声同期した状態にする
  2. ファイル → 書き出し → Final Cut Pro XML を出力（タイムライン情報をXMLで持ち出す）
  3. Claude Codeデスクトップアプリを起動 → XMLファイルをドラッグ＆ドロップ → /cut スキルを呼び出す
  4. 約20秒でカット済みXMLが出力 → Premiere Proに読み込み直すと、33分素材が22分に自動カットされている
  5. テロップは、編集済み動画をWAV書き出し → XMLと一緒にClaude Codeに投げて /srt スキルを実行 → 約10分でSRTファイル生成 → Premiere Proに読み込みでテロップ自動配置

重要なのは、Claude Codeの「スキル」は単なるマニュアル＝指示書ファイルであり、一度作っておけば /cut /srt というスラッシュコマンドで再現性高く呼び出せる点。河村さんはGitHub経由でスキル一式を公式LINE登録者向けに配布しており、メッセージ例をコピペして自分用にカスタマイズ（保存先・カット条件の緩急）できる設計になっている。

出力精度に関する重要な思想として、咳込み・言い直し・フィラーは意図的にカットさせない方針を採用。理由は「AIに判断を任せると、勝手にカットされて思いもよらぬ事故が起きる」ため。AIができることはAIに任せ、人間判断が必要な部分は手作業で残すというハイブリッド設計が紹介されている。

モデル選択は Sonnet 4.6推奨（Opusは過剰、Claude Codeのレート制限節約のため）。プランモード・許可バイパスはユーザーのリスク許容度で選択。

動画後半では、Claude Codeでアドビ用プラグインを自作する応用例も紹介。UXP Developer Toolsに自作プラグインを読み込ませ、よく使うテロップデザイン・演出（強調・縮小・不透明度ダウン）を Cmd+1 Cmd+2 … のショートカットで呼び出せるようにしている。さらに「Iruru（入れる）」という動画レビュープラットフォームも自作し、タイムコード付き修正指示・矢印・画像添付・倍速確認まで実装している。

市販のAI動画編集ツール（Vrew等）やClaude Code Video Use機能との比較として、それらは社外公開・クライアントワーク用途には精度不足だが、Premiere Pro × Claude Codeスキル方式は実用レベルだと結論づけている。

💡 ゆりこの活用メモ

ゆりこはPremiere Pro / AE / Mocha AE / Blenderで動画編集スキルあり（user_video_editing参照）なので、このフローはそのまま実務で効く。特に以下の使い所がある：

  • 講習動画・社内研修動画の編集自動化：Cowork講習・全社員向けAI研修・MD構成表説明動画などを撮ったとき、33分→22分カットが20秒で終わるなら撮影〜編集〜共有のループを劇的に短縮できる。
  • イベント・撮影記録の編集：Armillary.撮影・81fes・kemio関連の素材を社内共有用にカット＋テロップ付きで編集する用途。
  • MEADOW.メドウマガジン用ショート動画：月刊MEADOW Magazineの導線として、コレクション紹介ショート動画をPremiere Pro × Claude Codeで量産できる可能性あり。
  • /cut /srt スキルの自作化：河村さんが配布しているスキルをベースに、ゆりこ用に「フォント＝AvenirまたはARMILLARY指定」「テロップ位置＝下センター固定」「カット閾値＝0.5秒以上の無音」等カスタマイズしたスキルを ~/.claude/skills/ に格納する案がある。既存スキル群（skills_inventory）と統合可。
  • AIに任せない判断：咳込み・フィラー・言い直しは手作業にする方針はゆりこの「成果物クオリティ重視」スタンスに合う。AIで一括処理する誘惑を断つ。
  • アドビプラグイン自作：Claude Codeでアドビ用プラグインを自作できる事実は、デザイン部の制作自動化（project_design_workflow）の延長で活かせる。たとえばArmillary.の色補正プリセット呼び出し・Photoshopのスモークカットアウト自動化等。
  • 公式LINE経由のプレゼント：実際に試したいなら、まず河村さんの公式LINEでGitHubリポジトリを受け取り、ベースを把握してから自作版を作るのが最短ルート。
