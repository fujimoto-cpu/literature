morning-brief

Trigger

macOS launchd で毎朝6時。または手動で “Run morning-brief”。

Context Required

  • 04 - SYSTEM/CLAUDE.md (今週のフォーカス と アクティブプロジェクト)

  • 06 - GENERATED/briefings/ から最新のリサーチブリーフ3本

Process

  1. CLAUDE.md の「今週のフォーカス」を読む
  2. 過去7日の日次ノートを横断して、未処理の判断と継続テーマを抽出
  3. 直近のリサーチブリーフから、今日に直接関係するものを1-2件選ぶ
  4. 今日の優先事項を3つに絞る。各点に「なぜ今日か」の理由をつける
  5. 正午までに下す判断を1つ特定する

Output Format

保存先: 06 - GENERATED/briefings/[YYYY-MM-DD]-morning.md

Quality Standard

queue-processor

Trigger

07 - QUEUE/ にファイルが追加されたら起動。 fswatch で監視するか、手動で “Process queue file [filename]“。

Context Required

  • 04 - SYSTEM/CLAUDE.md (全セクション)
  • 渡されたファイル名のプレフィクスで処理を分岐

Process

ファイル名で分岐する。

  • RESEARCH-[topic].md → deep-research スキルに委任
  • DRAFT-[type]-[topic].md → content-draft スキルに委任
  • TASK-[name].md → 内容を読み、適切なスキルに委任 or 直接実行

委任後、QUEUE の元ファイルを 08 - ARCHIVE/queue/[YYYY-MM-DD]/ に移動する。

Output Format

委任先スキルが GENERATED/ の対応サブフォルダに出力する。 queue-processor 自身は処理ログだけ 04 - SYSTEM/logs/operations.md に 1行 append する。

LOG ENTRY: [timestamp] processed [filename] → [delegated skill]

Quality Standard

pre-call-brief

Trigger

  • 01 - PROJECTS/[client-name]/ 配下を全て

Process

Quality Standard

📝 要約

🎯 海外117,452人が読んだ「Obsidian Vault を Claude Code で事業OSに変える」記事を日本語で完全解説。一人事業がツールに飲まれる根本原因は「連携設計の不在」。8フォルダ構造＋Master CLAUDE.md＋5つの参謀システムで、朝起きたら仕事が進んでいる状態をつくる。

📌 ポイント

1. ツールを集めることと連携設計は別物

ChatGPT・Claude・Notionを個別に使っているだけでは「相談相手」止まり。一人事業が時間を失う構造は3つに集約される。①ツール連携設計の欠如、②共有記憶層の不在（ツールごとに別記憶でAIに毎回ゼロから説明）、③「戻ってこさせる装置」の不在（思い出して開かない限りツールは黙ったまま）。

2. Vault 8フォルダ構造 — 人間ではなくAIが読める前提で設計

00-INBOX（未処理着地点）、01-PROJECTS、02-AREAS、03-RESOURCES、04-SYSTEM（CLAUDE.md＋skills/）、05-DAILY、06-GENERATED（AIの自律出力）、07-QUEUE（AIへの仕事投入箱）、08-ARCHIVEの9フォルダ。QUEUE＝仕事を投げる箱、GENERATED＝仕事が返ってくる箱。GENERATEDは手で編集しないルールが重要。

3. Master CLAUDE.md は「事業の憲法」

04-SYSTEM/CLAUDE.mdの1枚に、オーナー情報・業務文脈・Vault構造・アクティブクライアント・コンテンツ運用・売上目標・自動運用ルール・品質基準・今週のフォーカスを10セクションで記述。全AIエージェントはこのファイルを読んでから動く。「今週のフォーカス」を毎週月曜5分で更新するだけで全判断の鮮度が保たれる。「更新されないCLAUDE.mdは古い回答しか返さない」。

4. 5つの参謀システム（各SkillファイルをMarkdown1枚で実装）

リサーチ参謀（QUEUE投下→朝6時に briefings着地）、コンテンツ参謀（Morning Content Briefで今日の角度3つ→DRAFT投下で翌朝下書き）、クライアント参謀（コール30分前にPre-Call Brief自動生成）、自己マネジメント参謀（毎週日曜20時に週次レビュー自動生成・45分→15分）、経理参謀（日次ノートに「RECEIVED:」1行で月次売上自動更新）。著者はn8nよりClaude Code Skills・AIワークフロー中心設計を推奨。

5. 自動化レイヤー5型 — 最初はCronの1本だけで十分

Cron（時間起動：朝6時Morning Briefing・日曜20時Weekly Review）、File Watch（QUEUEフォルダ監視・fswatch）、Event（カレンダー30分前通知→Pre-Call Brief）、Aggregation（複数ソース集約レポート）、Notification（GENERATED書込み時にmacOS通知）。全Skillが04-SYSTEM/skills/にMarkdown1枚で管理され、外部SaaSに業務ロジックを散らさない設計。

💡 ゆりこの活用メモ

① CORINとVaultはすでにこの設計を実装済み CLAUDE.md＝憲法、.claude/skills/＝参謀、/ohayoスキル＝Morning Briefingがすでに動いている。「死蔵庫」を避けるためGENERATEDに相当するnotesフォルダを手で編集しない運用を徹底するとさらに効く。

② KONNEKT AI推進提案のロジックに使える 「ツールではなく連携設計の不在」という言語化は、18名展開で「なぜClaude Codeだけ入れても変わらないのか」を説明する際に刺さるフレームワーク。
