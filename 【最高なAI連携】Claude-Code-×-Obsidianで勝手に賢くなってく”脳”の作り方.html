📝 要約

🎯 Claude Code と Obsidian を接続して、AIが自分で気づきをメモしていく「第二の脳」を作る方法を実演解説する動画。人間は記憶する負担から解放され、AIは次回作業の再現性を高めていく。

🗺️ 全体像

flowchart TD
    A[Obsidianボルトを作成] --> B[Claude Codeにフォルダを指定]
    B --> C[スキル作成: Obsidian保存用スキル]
    C --> D[Hooksでスキル作成を検知]
    D --> E[スキル完了時に自動でObsidianへメモ]
    E --> F[スキル一覧・NG表現リスト等が自律的に蓄積]
    F --> G[次回作業の再現性が向上]

📌 ポイント

1. Obsidianの正体はローカルフォルダのビジュアライザ

Obsidianは特別なDBを持たず、ローカルPC上のMarkdownフォルダをそのまま綺麗に表示するだけのメモアプリ。だからこそAIエージェント（Claude Code・Codex）が直接ファイル操作するのと相性がいい。Notion・Google Driveは同じことをAPI経由でしかできず、直接性で劣る。

2. スキル作成と同時にObsidianへドキュメント化する設計

スキルクリエイターでスキルを作るたびに、その使い方・呼び出し方・内部ロジックを自動でObsidianの「スキル一覧」フォルダにメモさせる。スキルが50個を超えても「このスキルどう使うんだっけ」をObsidianを見返すだけで思い出せる状態を作れる。

3. Hooksで「メモし忘れ」を構造的に防ぐ

スキル作成の都度メモするのを人間の意識に頼ると忘れる。そこでHooksイベント（スキル作成を検知したら自動で指定スキルを実行）を自然言語で作成し、スキル作成→自動Obsidian保存を機械的に固定する。「これをメモすべきか」の判断もAI側に持たせる設計思想。

4. NG表現リスト／良い表現リストで文体を学習させる

「この言い回しはやめて」と言うたびにObsidian上のNGリストへ追記される仕組みを作ると、AIの文章のクセが徐々に改善されていく。本の執筆・記事作成でも、章ごとのトンマナや過去の言い回しをObsidianに貯めて次のページ生成の参照にすることで、執筆効率が大きく上がる。

💡 ゆりこの活用メモ

① 「メモすべきか」の判断ごとAIに渡す発想を、既存の自動保存ルールに重ねる CORINには既に auto-save.md で意思決定・学び・アイデアの自動保存先があるが、この動画の「スキル完了時に必ずObsidianへ書く」設計は .claude/rules/skill-single-source-of-truth.md の思想と同じ方向。新しいスキルを作るときは「完了時にメモ先を明記する」を標準手順に加えると良さそう。

② NG表現リストの仕組みは既にcritical-mistakes.mdでやっていることに近い 「評価っぽい相槌を入れない」等のNGパターンはCORINでもcritical-mistakes.mdに蓄積済み。今後CORINに「その言い回しやめて」と言ったら、その場でそのメモリに追記する運用を明確にしておくと、この動画の設計に近づく。

③ Hooksによる自動化の発想は、CORINの正規表現hookと同じ構造 「スキル作成を検知して自動実行」は、CORINの .claude/scripts/task-link-inject.py（発言を検知してスキル全文を注入）と同じ設計思想。新しい繰り返し作業に気づいたら、同様のhook化を検討する価値がある。
