📝 要約

🎯 Claude Codeを「ハーネス」として正しく理解し、.claudeフォルダ・Hooks・Compaction・Branch・Sandbox・Permissionという6つの基礎手段を体系的に解説する京大博士によるディープダイブ動画。

🗺️ 全体像

flowchart TD
    A[ハーネス理解] --> B[.cloudフォルダの構成把握]
    B --> C{入出力の品質向上}
    C -->|決定論的実行| D[Hooks：特定タイミングでスクリプトを強制実行]
    C -->|履歴の最適化| E[Compaction：コンテキスト圧縮設定]
    C -->|分岐と複製| F[Branch：セッションを並行運用]
    A --> G{安全な環境を作る}
    G -->|ファイル隔離| H[Sandbox / Docker]
    G -->|権限の多層管理| I[Permission：allow/ask/deny]

📌 ポイント

1. Hooks — 決定論的に動くプログラムの設定

settings.jsonのhooks項目に「ツール使用前後・セッション開始・Compaction後」などのタイミングを設定し、必ず実行したいシェルスクリプトを登録できる。例：「mainブランチへの直接コミットを禁止するprotect-main.sh」「ファイル編集後に必ずリンターを実行」「Post-Compactで重要ルールをプロンプトに再注入」など。CLAUDEに「やって」と頼むよりも確実に動く。

2. Compaction — コンテキスト圧縮のチューニング

デフォルトで83.5%を超えるとメッセージ履歴を自動圧縮（要約に変換）する。settings.jsonの CLAUDE_AUTO_COMPACT_PERCENTAGE_OVERRIDE で任意の閾値に変更可能。発表者は60%に設定し、Post-Compactフックで必要情報を再注入する設計を採用。

3. Branch — セッションの分岐と作業ディレクトリをまたいだ複製

/branch コマンドで現在の会話履歴を複製し、別の方向で探索できる。さらに ~/.claude/projects/ 配下のJSONLファイルを別ディレクトリに手動コピーし、/resume で再開すれば異なる作業ディレクトリでも同じ履歴を活用できる。調査→実装の連携に有効。

4. Sandbox と Permission — 多層的な安全設計

Claude Code標準のSandboxはバグが多く現状非推奨。代わりにDockerコンテナ（Dev Container）で作業ディレクトリだけをマウントして実行するのが安全。Permissionはdeny→ask→allowの順に評価され、.envファイルへのReadをdenyするなど多層的に設定する。

💡 ゆりこの活用メモ

① 明日、Claude CodeのHooks設定を確認してPost-Compactフックを1つ追加してみる セッションが長くなると人格が消えることが課題なら、圧縮後に重要なルール（秘書ちゃんの設定など）を自動再注入するフックで解決できる。settings.jsonを開いて hooks.postCompact に追記するだけ。

② セッション履歴のcleanupperioddaysを99999に変更して長期保持する 過去のセッションを参照して続きから作業するBranch活用のためには履歴保持が必要。settings.jsonの cleanupPeriodDays を大きい値にしておく。
