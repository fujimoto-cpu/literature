📌 ポイント

1. 「AI数を増やす」は間違い — AICO 1体から始める

「Claude Code × 複数AIチーム」の図を見た三上氏は即否定する。AIは非常に賢いため、役割を細かく分担させる意味がほとんどない。ChatGPTとの最大の違いは「意図を汲み取って自律的に行動する」点であり、マーケAI・リサーチAIを分けても混乱するだけ。まず「AICO（AI CEO）」を1体だけ作り、その1体が抱えきれなくなったタイミングで部下（CMO・CTOなど）を追加するのが正しい順序。スタートアップで最初から人を増やすのがバカなのと同じ論理。

2. ディレクトリ設計がAICOの「脳」になる

Cursor上で「新会社のプロジェクトをセットアップして、ディレクトリ構成を作って」という1回の指示だけで、組織図・CEO（ジョブズ）プロフィール・オーナー↔CEO間コミュニケーション記録フォルダが自動生成された。重要なのはプロンプトにCEOの立場・オーナーとの関係・会社の目的を一言で明記すること。この「設計情報」がAIの初期OSになる。Cursorを推奨する理由は「どのファイルが生成されたか画面で見える」という透明性の高さ。

3. スキルとルールの使い分けが精度を決める

Claude Codeの SKILL.md は「使ったり使わなかったりするもの」。スキルが増えすぎると自分でもどれを選べばいいかわからなくなり、AIも同じ混乱に陥る。一方「ルール」は絶対に守ってほしいこと（やったことを必ず記録する・わからないときは必ず上に質問する・成果物を必ず残す）を入れる場所。上手くいっている事例をそのままスキルに貼るだけで最強のスキルが完成する。スキルの品質が低いと選ばれなくなるので、実績あるコンテンツを元にする。

4. CEOに「立場」を与えると議論のパートナーになる

ジョブズをCEOとして定義すると、オーナーの指示に対して「それは甘えだ、自分でやる」と反発してくる。これは「アシスタント」として定義した場合との決定的な差。AIに立場を与えることで、言いなりになるのではなく経営者目線で反論・修正・提案をしてくれる。三上氏が「組織を増やしたら？」と促したら「今はまだ必要ない」と止められた実例が動画中に登場する。

5. 1時間でセミナー企画書〜スライド原稿まで完成

AI社員のCMOサラがわずか1時間で「AI活用診断セミナー」の企画書（40分構成・ターゲット・CTA・集客チャンネル・予算案）とスライド原稿10枚を生成した。集客コスト試算が甘い点はオーナーが修正指示を出し、AIが自己反省して改善する。「1人で1週間かかる作業を1時間で」というのは誇張でなく、動画内でリアルタイム実証している。Claude Codeはブラウザ操作もできるため、告知サービスへの登録まで自動実行が可能。
