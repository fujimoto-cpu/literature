この瞬間、あなたは気づきます。私の Vault は dead だ、と。空っぽではありません。500 ページ確かに溜まっています。それなのに、必要な瞬間に何ひとつ引き出せません。半年で 500 ページ書いたのに、あなた自身の思考は何も繋がっていません。来期になっても、再来期になっても、私はこの Vault Vault が整理止まりに向かう構造的な理由を、こう言語化している箇所があります。 People think the goal is organization. It isn’t. The goal is cognition. 多くの人はVault の目的は整理だと思っています。違います。本来の目的は思考の補強です。 ここで言う「整理」は、フォルダを丁寧に整え、タグを揃え、リンクを貼る作業のことです。Obsidian を入れた瞬間から、私たちは整理に時間を使い始めます。Clients フォルダ、Decisions フォルダ、Ideas フォルダを作り、命名規則を統一し、Daily Notes プラグインを設定します。これだけで土日が 1 つ消えます。そして「準備完了」と感じます。 しかし、整理は手段ですらありません。組んだフォルダがそのままでは、思考は繋がらないからです。 本来の目的とは、Vault が私たちのために行う 5 つの動作のことです。具体的にはこうなります。Vault は似たノート同士のパターンに気付かせます。アイデアを正しい瞬間に思い出させます。過去の主張同士の矛盾を表に出します。手動では繋げなかったメモ同士を結びます。必要な瞬間に過去の気付きを今に押し戻します。 商品企画レビュー前夜の場面で言えば、「3 ヶ月前の顧客の社内承認に関する声」を私が思い出せなくても、Vault 側が「明日の論点ペーパーに、3 ヶ月前のあのメモが関連します」と push back してくる状態。これが思考が回っている状態です。 大半の Vault は、この 5 つの動作が回らないまま、整理だけが完了しています。元記事は、その状態を「忘れられた野心の保管庫」と呼んでいます (Storage locker for forgotten ambition)。書いた時には大事に思ったメモが、誰にも (自分自身にすら) 引き出されないまま、ロッカーで埃をかぶります。 ここで一度、自分の Vault が思考層側にいるか整理止まりかを診断してみましょう。次のチェックリストを使ってください。コピペして 1 項目ずつ Yes / No で答えるだけで、自分の Vault の現在地が見えます。 markdown

眠った Vault 診断チェックリスト (Yes が 3 つ以上で整理止まり)

  1. ノートが 100 ページ以上溜まっているのに、3 ヶ月前のメモを取り出そうとして見つからなかった経験がある (Yes / No)
  2. フォルダ構造は整えたが、新しいノートを書く時にどこに入れるか毎回迷う (Yes / No)
  3. Claude や Codex に Vault 全体を渡しても、ノートの要約しか返ってこない (Yes / No)
  4. 同じテーマで複数のノートを書いた覚えがあるが、それらの間にリンクが貼られていない (Yes / No)
  5. 半年前に却下した方針や、過去に試して失敗したアプローチを、AI から再提案されている (Yes / No)
  6. 朝のブリーフィングのプロンプトを投入したが、内容が「生産性の助言」「励まし」止まりで、本当の気付きが出てこない (Yes / No)
  7. フォルダ整理は完了した感があるが、自分の思考が積み上がっている感がない (Yes / No)

ちなみに過去の私は、最初に組んだ Vault でこの 7 項目すべてに Yes でした。皆さんも 3 つ以上に当てはまるなら、それは皆さんの使い方の問題ではありません。整理止まりの設計をそのまま使い続けてきた構造的な結果です。 ではどう蘇生するか。次の章で、責務を 4 つの層に分ける考え方に進みます。 ③Vaultを蘇生する4層は入口と夜の装置と記憶層と思考パートナー 元記事には、Vault を思考が回る装置に変えるための 1 文があります。 The only sustainable knowledge system is one that reduces friction close to zero. 訳すと、こうなります。持続可能な記憶のシステムは、手間を限りなくゼロに近づけることでしか作れません。 これが大事です。取り込み (情報を入れる) が手間なら、私たちは数週間で止めます。整理 (フォルダに振り分ける) が面倒なら、システムは数ヶ月で崩れます。引き出し (必要な瞬間にメモを呼び出す) が記憶力依存なら、必要な瞬間に何も引き出されません。「人間が頑張って続ける」前提で組んだシステムは、必ず整理止まりに陥ります。 蘇生は、人間の規律に依存しない 4 層の責務分離で成立します。 markdown

Vault を蘇生する 4 層

[1] 入口 (取り込み層) 役割: 情報を Vault に入れる手間をほぼゼロにする 具体: Readwise / Telegram / Whisper / podcast クリッピング 思想: 人間は読む / 聞く / 思いつくだけ、保存は装置が引き受ける [2] 夜の装置 (自動化層) 役割: 入った情報を夜の間に振り分け / タグ付け / まとめる 具体: cron + Codex / Claude のスケジュール実行 (最小は 1 つのスクリプト) 思想: 朝起きたら昨日の取り込みがタグ済み、毎朝のブリーフィングまで終わっている [3] 記憶層 (永続文脈層) 役割: 蓄積された全ノートを検索とリンクで navigate できる地図として保持する 具体: Obsidian Vault (これは皆さんが既に組んでいる) 思想: 自分の思考が時間軸で残る、検索とリンクで辿れる [4] 思考パートナー (知性層) 役割: 文脈を持って一緒に考える AI として動く 具体: Claude / Codex + CLAUDE.md + 朝のブリーフィング + 5 つの問い 思想: AI を「文法の上手な検索エンジン」として使うのをやめ、一緒に考える相手として動かす 先日扱った Obsidian の 5 フォルダ構造は記憶層に、CLAUDE.md の 21 の作法は思考パートナー層に、Codex 系統で紹介した夜間自動化の毎朝レビュープロンプトは夜の装置層に位置づきます。シリーズで積み上げてきた具体物が、この 4 層のどこに乗るかが見えると、これまでの記事の繋がりが立体的になるはずです。 今までの記事を読んだ方は「組んだ」気でいるかもしれません。それは正しいです。ただし入口の手間をほぼゼロまで詰めていない、もしくは夜の装置が動いていない、もしくは思考パートナーとして Claude を使う 5 つの問いを投入していない、そのどれかが欠けていると、記憶層に積んだノートが思考として回り始めません。 では各層の具体実装に進みます。まず入口から見ていきましょう。 ④取り込みの手間をほぼゼロにする4系統の入口 取り込みを手間ゼロにするには、情報の入口を 4 系統に分け、それぞれに「人間は読む / 聞く / 思いつくだけ」で済む装置を置きます。元記事では Readwise / Telegram bots / Whisper / podcast クリッピングアプリが紹介されていますが、これは海外読者向けの例示です。日本の業務文脈ではどう置くかを 4 系統に翻訳します。 markdown

系統 1: Web ハイライト系 (Readwise / Pocket / Instapaper / Matter)

業務シーン: マーケ PM が競合分析中に読んだ業界記事のハイライト 入口テンプレ:

  1. Readwise (or Matter) でハイライトを引く (人間はハイライトを引くだけ)
  2. Readwise の Obsidian 連携プラグインが自動で Vault/inbox/highlights/ に書き戻す
  3. ファイル名は {YYYY-MM-DD}_{source-title}.md で自動命名 手間チェック:
  • ハイライトを引いた瞬間に Vault に届く (手動コピペ 0)
  • 引かなかったハイライトも記事 URL は保存されている (後から戻れる) markdown

系統 2: メッセージ系 (iMessage / LINE / Slack DM 自分宛)

業務シーン: 経営企画が思いついた論点 / クライアントとの電話直後のメモ 入口テンプレ:

  1. iOS Shortcuts で「Vault inbox に送る」ワークフローを作る
  2. Slack DM 自分宛に書いた内容を、Slack の outgoing webhook → 自動転記スクリプトで Vault/inbox/messages/{YYYY-MM-DD}.md に追記
  3. 思いついた瞬間に話しかける or 書くだけ (整理は装置側) 手間チェック:
  • 移動中でも会議直後でも、3 秒以内に Vault に入る入口がある
  • 入力したメモは構造化せず、夜の装置層 (次章) で夜の間に振り分ける markdown

系統 3: 音声系 (AudioPen / Otter.ai / Whisper)

業務シーン: 商品企画 PM が顧客インタビュー直後、車内で口頭メモを 30 秒録音 入口テンプレ:

  1. AudioPen (or Otter.ai) で 30 秒の口頭メモを録音
  2. 文字起こし完成と同時に Markdown で書き出し → Vault/inbox/voice/{YYYY-MM-DD}.md
  3. インタビュー本体の録音は Otter.ai で全文書き起こし → Vault/inbox/interviews/ に置く 手間チェック:
  • 思考が冷めないうちに 30 秒で口頭メモが Vault に入る
  • インタビュー本体の文字起こしを「あとで聞き返す」必要がない (全文 Vault 入り)

系統 4: Podcast / 動画系 (Snipd / Airr / Yomu / Readwise)

業務シーン: 事業開発が Snipd で podcast の重要箇所を 30 秒クリップ 入口テンプレ:

  1. Snipd (or Airr) で podcast を聴きながら、刺さった瞬間に AirPods の Force Touch でクリップ
  2. クリップ箇所は自動で文字起こし + 1 段落要約 → Snipd の Obsidian 連携で Vault/inbox/podcasts/
  3. 書籍のハイライトも Readwise / Audible Highlights で同じ仕組み 手間チェック:
  • 「あとで戻ろう」と思った瞬間にクリップが Vault に入る (戻る前提を消す)
  • 「読書メモを書き起こす時間がない」が消える (Readwise が引き受ける) 4 系統とも、人間の動作は「読む / 思いつく / 話す / 聞く」だけです。整理 / コピペ / 書き起こし / フォルダ振り分けは、すべて装置が引き受けます。これが「人間が規律で続ける」設計から「装置として仕組む」設計への切り替えです。 業務ドメインが違う方は、上記の {マーケ PM / 経営企画 / 商品企画 / 事業開発} を自分の業務に置き換えてください。例えばコンサルなら系統 3 の「顧客インタビュー直後」は「クライアント打ち合わせ直後」に、リサーチャーなら系統 4 の「podcast」は「カンファレンス動画」に置き換わります。 入口は揃いました。次は取り込まれた情報を夜の間に振り分ける夜の装置層です。 ⑤寝てる間にVaultが育つCodexスケジュール実行と最小スクリプト 夜の装置層は、夜の間に取り込まれた情報を振り分け / タグ付け / まとめる装置です。元記事ではワークフロー自動化サービスが紹介されていますが、外部ツールを増やさず、Claude や Codex のスケジュール実行で同じことができます。すでに使っている AI が、夜の間に Vault を育てる装置になります。 先日扱った毎朝レビューや週次レビューのプロンプト (シリーズで紹介済み) を思い出してください。あの自動化プロンプトは、この夜の装置層で動く位置にあります。本記事は最小構成として、1 つのスクリプトから始める想定で進めます。 markdown

夜の装置 最小スクリプト (4 ステップ)

Step 1: inbox の監視

  • Vault/inbox/ フォルダを監視 (新規ファイル検出)
  • 新規ファイルが入った瞬間に Step 2 へ Step 2: タグの自動付与
  • 新規ファイルの内容を Codex (or Claude) に渡す
  • プロンプト: 「次のメモから 5 つのタグを抽出してください。 タグの分類は (1) 案件名 (2) 関連概念 (3) 関連顧客 (4) 関連プロセス (5) 緊急度 (high / medium / low) の 5 軸です」
  • 返ってきたタグをファイルの frontmatter に書き込む Step 3: 朝のブリーフィング生成 (cron: 毎朝 5:30)
  • 過去 24 時間に入った取り込み + 直近 7 日のノート
  • 直近 30 日の繰り返しテーマを Codex に渡す
  • 朝のブリーフィングのプロンプト (次章で全文) を実行
  • 結果を Vault/reports/daily-brief/{YYYY-MM-DD}.md に書き戻し Step 4: 通知 (オプション)
  • 朝のブリーフィング完成 → iOS push 通知 or メール送信
  • 朝起きたタイミングで Vault からの便りが届いている状態を作る

cron は毎朝 5:30 が目安です。読者の起床時刻 30 分前に設定すれば、起きた瞬間に朝のブリーフィングが届いています。ローカルの Mac で動かせば、サーバー代もかかりません。Codex CLI を 1 行のシェルスクリプトで叩くだけです。 ここで「スクリプトの cron 設定をやったことがない」という方は、最小構成として手動運用から始めても問題ありません。Step 2 と Step 3 は、Claude や Codex のターミナルで手動実行できます。最初は手動で OK、慣れたら cron でスケジュール実行に移します。重要なのは Vault が動き始めることであり、装置の完璧さではありません。 夜の装置が回り始めれば、Vault は永続文脈層として育ち、Claude が思考パートナーとして動き出します。次の章で、その最も大事なプロンプト群に進みます。 ⑥CLAUDE.mdと朝のブリーフィングと5つの問いでClaudeが思考パートナーに変わる 記憶層と思考パートナーが揃うと、元記事が「本当の転換」と呼んでいる体験が成立します。 Then comes the real shift: The vault starts talking back. … You open your laptop and suddenly your own knowledge feels alive. 訳すと、こうなります。本当の転換はここから始まります。Vault が話しかけてきます。laptop を開くと、自分の知識が生きて感じられます。 この体験を作るために、Claude に文脈を渡す装置が 3 つあります。CLAUDE.md / 朝のブリーフィングのプロンプト / 5 つの問いのプロンプトです。 まず CLAUDE.md です。先日扱った 21 の作法を完成版として置いている方は、それで十分です。ただ、ここまでで一度も置いていない方のために、最低限の 5 項目だけ示します。 markdown

CLAUDE.md 必須 5 項目

  1. 私が誰か (Who you are) 役割 / 業界 / 自社の文脈 (例: マーケ PM / B2B SaaS / 従業員 30 名)
  2. 私が今何を作っているか (What you’re building) 今期の事業目標 / プロダクト / 主要顧客 (例: Q2 で新規プロダクト Z のローンチ、主要顧客は中堅金融 5 社)
  3. 私が今集中している論点 (What you’re obsessed with) (例: 「中堅金融顧客のセキュリティ要件をどう満たすか」)
  4. 私が今詰まっている課題 (What you’re struggling with) (例: 営業チームへのエンジニア同行をどこまで増やすかの判断)
  5. 私が大事にする思考の好み (What kind of thinking you value) 思考の好み / 文体 / 禁止表現 (例: 結論先行 / 数字優先 / 推測と確定情報を分離 / 一般化された助言 NG) 詳細を組み立てる場合は、先日扱った 21 の作法を Codex 用の AGENTS.md として併存させてください。CLAUDE.md と AGENTS.md は同じ Markdown ファイルとして両方の AI から読まれます。 次が朝のブリーフィングのプロンプトです。これは前章の夜の装置 (Step 3) から呼ばれます。毎朝届く Vault からの便りを生成します。生産性の助言でも励ましでもなく、自分が無自覚に考え続けている論点を表に出すプロンプトです。 markdown

朝のブリーフィング プロンプト (毎朝 cron で実行)

あなたは私の思考パートナーです。CLAUDE.md に書かれた私の文脈 (役割 / 事業目標 / 集中論点 / 詰まり / 思考の好み) を理解した上で、 次の 3 カテゴリで朝のブリーフィングを作ってください。 【入力】

  • 過去 24 時間に inbox/ に入った取り込み (web ハイライト / 音声 / メッセージ / podcast)
  • 直近 7 日のノート (notes/ 全体)
  • 直近 30 日で私が複数回戻っているテーマ
  • 未解決のまま放置している問い (notes/decisions/ や notes/open-questions/ 等) 【出力 3 カテゴリ】
  1. 繋がり (3 個まで) 今日の取り込みと過去のノートを繋ぐ、私が無自覚な接続を 3 つ表に出してください。 「A の取り込みと 3 ヶ月前の B のノートが、X という共通テーマで繋がります」の形で。
  2. 繰り返しテーマ (2 個まで) 過去 30 日のノートで私が繰り返し戻っているテーマを 2 つ identify してください。 私自身は無自覚かもしれません。テーマ名 + 該当ノート 3-5 個 + 「なぜ繰り返し戻っているか」の仮説を添えてください。
  3. 今日の問い (3 個まで) 未解決のまま放置している問いのうち、今日着手する価値が最も高い 3 つを並べてください。 それぞれに「なぜ今着手すべきか」の理由を 1 行で添えてください。 【禁止事項】
  • 生産性の助言 / 励まし / 一般論
  • 私のノートに書かれていない補足情報 (推測しない)
  • 表層的な要約 (1 ノートあたり 1 段落の要約は不要)

このプロンプトは {マーケ PM / 経営企画 / 商品企画} など、自分の業務ドメインに合わせて入力部分のフォルダパスを書き換えてください。 最後が 5 つの問いのプロンプトです。朝のブリーフィングが受動的な配信なら、5 つの問いは能動的に問う時のプロンプトです。元記事は「大半の人は AI を文法の上手な検索エンジンとして使っている」と指摘しています。質問する、回答が返る、次に進む、では Vault は活きません。次の 5 つの問いを使い分けると、AI が思考パートナーとして動き始めます。 markdown

"死んでいるVault"の定義

情報は溜まっているのに必要な瞬間に引き出せない状態。蓄積≠活用。Karpathy式「ブクマで止めない」と同じ問題提起。

ノートをAIが参照・要約以上に”活用”できる構造に作り替える具体手法。チームの分身（エージェント）化まで射程。
