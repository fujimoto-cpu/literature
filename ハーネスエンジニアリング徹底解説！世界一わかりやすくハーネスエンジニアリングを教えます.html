📝 要約

🎯 「ハーネス」とはAIモデルの外側にある仕組み全部のこと。モデル（脳みそ）が判断したことを実際の検索・実行・確認につなげる部分を自分で設計・育てていくのがハーネスエンジニアリング。

🗺️ 全体像

flowchart TD
    A[依頼が来る] --> B[モデル=脳みそが判断する]
    B --> C[ハーネス: 資料を見せる・道具を使わせる]
    C --> D[ツール実行・検索・結果取得]
    D --> B
    B --> E[ハーネス: 送信前に止めて確認]
    E --> F[ハーネス: 確かめて修正を戻す]
    F --> G[完成物が人に届く]

📌 ポイント

1. モデルは脳みそ、ハーネスは手足

AIモデル（クロードコードの中のOpus/Sonnet、GPTなど）は「次に何をするか」を判断するだけで、自分で検索したりファイルを開いたりはしない。実際に検索・実行・記憶するのはモデルの外側の仕組み＝ハーネス。モデルは脳みそ、ハーネスは手足だと捉えると理解しやすい。

2. 定義が割れているのは「線引き」の違いだけ

「モデル以外は全部」「実行を回す進行役の部分だけ」「クロードコードやCodexという製品そのもの」「利用者が足していく仕組み」など複数の定義があるが、どれも対立していない。同じ図の中でどこまでをハーネスと呼ぶか、線を引く場所が違うだけ。

3. Agent = Model + Harness（LangChainの定義）

モデル自体は選ぶことしかできない（Opus・Sonnet・GPTなどを選択するだけ）が、ハーネスは自分で設計・改善できる。だからこそハーネスの質がエージェントの精度を決める。モデルが賢くなったからこそ、判断を実行に変える手足側の設計が重要になってきている。

4. ハーネスエンジニアリングの実践＝5つの動詞

「見せる（何を材料として渡すか）」「使わせる（どのツール・データに接続させるか）」「繋ぐ（結果を次の判断にどう渡すか）」「止める（送信・上書きなど外に影響する操作の前に人が確認する）」「確かめる（数字・出典・基準を満たしているか検証し、問題があればモデルに戻す）」。この5つの往復を整えていく作業がハーネスエンジニアリング。

5. 最初の一歩はファイル設計（エージェントの指示書＋補助ファイル）

クロードコードのCLAUDE.md、Codexのagents.mdのように、モデルが必ず読みに行く中枢ファイルがまず入り口。そこにpurpose.md（目的・読み手）、workflow.md（進め方）、checks.md（確認条件）などの補助ファイルへの導線を書いておくと、MCPやコネクター接続と同じように「モデルに何を見せるか」を仕組み化できる。失敗した内容をその都度ファイルに書き残すことで、同じ指摘を繰り返さなくなる。
