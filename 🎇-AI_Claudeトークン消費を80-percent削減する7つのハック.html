Most people run out of tokens early because of how they use Claude, not how much they use it.

Every message carries past context, so longer chats slowly become expensive.

A simple shift helps: give cleaner inputs.

Remove extra words, avoid repeating context, and be specific.

This reduces how much Claude has to process each time.

Also, Claude doesn’t need your full data every time.

If you share only the important parts (like summaries or key points), it performs the same task with fewer tokens.

Model choice also matters. Using a heavier model for simple tasks increases token usage without adding real value.

Think of it like this: the clearer and shorter your input, the less work Claude has to do. And the longer your session lasts.

スライド 2（Hack #1）

The “Caveman” Method

  • Make Claude talk like a caveman.
  • No filler. No yapping. Direct answers.

Use this exact prompt:

“From now on, remove all filler words. No ‘the’, ‘is’, ‘am’, ‘are’. Direct answer only. Use short 3-6 word sentences. Run tools first, show the result, then stop. Do not narrate. Example: Instead ‘The solution is to use async’, say ‘Use async’.”

This will save ~40% tokens per response.

スライド 3

See The Difference:

WITHOUT CAVEMAN:

“I’d be happy to help you with that! The best approach for this would be to implement an async function. You’ll want to make sure that you’re using proper error handling as well…” [127 tokens]

WITH CAVEMAN:

“Use async function. Add try-catch block. Handle errors with .catch() or await.” [32 tokens]

Same info but 75% less tokens.

スライド 4（Hack #2）

Use Code Review Graph Stop making Claude read your entire codebase over and over.

Check it out here: /github.com/tirth8205/code-review-graph (Public)

  • Turns your code into a structured map.
  • Claude sees the structure, not every line.
  • Saves 60-70% tokens on code projects.

スライド 5（Hack #3）

Don’t Use Opus All Time! Opus burns 5x more tokens than Sonnet.

USE SONNET FOR:

  • Code implementation • Data analysis
  • General questions • Document summaries

USE OPUS FOR:

  • Complex architecture decisions
  • Critical bug diagnosis • Nuanced writing

USE HAIKU FOR:

  • Quick answers • Non-logical tasks
  • Simple daily tasks

スライド 6（Hack #4）

Never Upload PDFs Directly To Claude PDFs can consume 80% of your session. So do this instead:

  1. Upload the PDF to ChatGPT first
  2. Use this prompt: “Read this document thoroughly. Remove all filler words, extra text, & formatting. Extract the core info. Return as condensed plain text with key points.”
  3. Copy the output given by ChatGPT
  4. Paste into Claude

スライド 7（Hack #5）

The Session Timing Trick Your 5-hour window starts with your FIRST message. So follow this trick:

// Send a basic message 2-3 hours before you actually need Claude. For example: 6:00 AM - Send something like “hey” 9:00 AM - Start the real work 11:00 AM - Your window resets mid workflow

Fresh allocation when you need it the most.

スライド 8（Hack #6）

Create a “Compact” Skill

  • Long chats eat tokens exponentially.
  • But switching chats = losing context.

Use this exact prompt:

“Create this skill: When I say ‘COMPACT’, summarize our entire conversation into 5-7 key bullet points with all critical context, decisions, & code snippets. Format for easy copy-paste into new chat”

This creates a Compact Conversation Skill.

スライド 9（Hack #7）

Avoid Peak Hours Peak hours = faster token burn.

WORST TIMES:

  • Weekdays 5am-11am PT
  • That will be 1pm-7pm GMT

BEST TIMES TO USE CLAUDE:

  • Weekends
  • Weekday evenings
  • Late night / early morning

🗣️ プロンプト最適化系

Hack #1: ケイブマンメソッド（約40%削減） 「フィラーワード禁止・3〜6語の直接回答のみ」と指示するプロンプトを冒頭に置く。127トークンの回答が32トークンに圧縮される（75%削減）。Claude Codeのシステムプロンプト or CLAUDE.mdに1行追加するだけで即効果あり。

Hack #6: Compactスキルの作成 「‘COMPACT’と言ったら会話を5〜7箇条に要約してコピペできる形式で出力するスキルを作って」と一度指示するだけ。長期セッションのコンテキスト維持とトークン節約を両立できる。

🛠️ ツール・モデル選択系

Hack #2: Code Review Graph（60〜70%削減） コードベース全体を構造マップに変換するOSSツール。Claudeが全行を読む必要がなくなる（github.com/tirth8205/code-review-graph）。

Hack #3: モデルを使い分ける Opusはsonnetの5倍トークンを消費する。コード実装・データ分析・一般質問 → Sonnet、複雑なアーキテクチャ・クリティカルなバグ診断 → Opusと使い分けることで全体コストを大幅削減。

Hack #4: PDFはChatGPTで要約してから渡す PDFを直接Claudeにアップロードするとセッションの80%を消費する可能性がある。ChatGPTで「フィラー除去・要点抽出」させてテキストをペーストする方が大幅に節約できる。

⏰ 運用タイミング系

Hack #5: セッションタイミングトリック 5時間ウィンドウは最初のメッセージで開始する。本番作業の2〜3時間前に「hey」等を送り、ウィンドウをリセットしてから本作業を開始する。

Hack #7: ピーク時間帯を避ける 平日5am〜11am PT（JST 21時〜翌3時）はトークン消費が速くなる。平日夜・週末・深夜/早朝が最適。
