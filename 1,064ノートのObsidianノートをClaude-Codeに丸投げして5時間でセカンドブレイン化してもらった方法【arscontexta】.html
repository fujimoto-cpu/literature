📝 要約

🎯 1,064件の既存Obsidianノートを Claude Code に丸投げして6ステップでセカンドブレイン化する手順を、非エンジニア向けに解説した動画。arscontexta（Earth Context）プラグインとサブエージェントの3層構造を活用し、元ノートを一切書き換えずにAtomicノートのグラフを構築できる。

🗺️ 全体像

flowchart TD
    A[Step 0: バックアップ\nフォルダを丸ごと複製] --> B[Step 1: 実装\nサブエージェント定義ファイルを配置]
    B --> C[Step 2: 設計\n除外リスト作成＝棚卸し]
    C --> D[Step 3: テスト\nサブフォルダ10ファイル以内で試走]
    D --> E[Step 4: 実行\n約50ファイル単位でバッチ処理]
    E --> F[Step 5: 確認\nグラフビューで検証 + CLAUDE.md更新]

📌 ポイント

1. 3層サブエージェント構造 — コンテキストを汚さず重い処理を分担

メインClaude Code（会話窓口）→バッチ取り込みサブエージェント（ファイル検出・積み込み）→パイプラインサブエージェント（抽出・接続・検証）の3層構造。重い処理は専用の新鮮なコンテキストに切り出すことで、メインの応答精度を維持する。なお、3層構造がフル動作するのはClaude Code CLIのみ。Claude.aiのWebブラウザ版では一部サブエージェントが失敗することがある。

2. 除外リスト設計（棚卸し）— ノイズを先に弾く

AI会話履歴・添付ファイル・自動生成ログなどをAtomicノート化するとノイズになる。処理前にClaude Codeと会話して除外すべきフォルダを洗い出し、除外リストを作成してから実行する。この設計を飛ばすとグラフがノイズだらけになる。

3. スモールテスト必須 — 10ファイル以内のサブフォルダで試走

いきなり全ノートを処理しない。まず10ファイル以内のサブフォルダに絞ってテストバッチを実行し、①期待通りのインサイト・つながりが出るか、②除外設定が効いているか、③サブエージェントが最後まで走り切るか、を確認する。本番のバッチ単位（著者は約50ファイル）もテスト結果から相談して決める。

4. CLAUDE.md への追記 — 新セッションでもグラフを参照させる

arscontextaが機能するにはVaultトップのCLAUDE.mdに①ディレクトリ構造と②「会話の中で必ずグラフを参照すること」の参照ルールを明示的に追記する必要がある。この設定がないと新しいClaudeセッションがグラフを無視して動く。

💡 ゆりこの活用メモ

① 今の corin Vault にそのまま使える すでに LiteratureNote/StructureNote の4サイクル（Ingest/Compile/Query/Lint）は動いている。arscontexta を追加導入すれば、既存の1,000件超のノートをバッチでグラフ化できる。まず.claude/agents/配下にサブエージェント定義ファイルを1つ置くだけで試せる。

② テストは LiteratureNote/ の10件以内のサブセットで いきなり全件走らせない。LiteratureNote/の中の処理済みノート10件を選んでテストバッチを回し、サブエージェントが正しく動くか確認してから本番実行する。
