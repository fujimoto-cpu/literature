📌 ポイント

1. AIの役割転換 — アドバイザーからスタッフへ

ここ1〜2ヶ月でAIが直接Macを操作できるようになったことで、AIは「質問に答える人」から「頼んだら成果物まで作って出してくれる人」に変わった。今までは聞いても結局自分で手を動かす必要があったが、いまは指示を出すだけでAIが考え・実装・テスト・完成まで一気通貫でやる。「ドラえもんが家に来た感」「なろう系主人公の全能感」と表現するほどの体験変化で、iPhone登場時に匹敵する世界の変わり方だと位置づけている。

2. Cメール — Gmail+学習するAI返信

Geminiの自動返信は便利だがカスタマイズ性が低く、複数Gmailアカウント運用だと課金コストもかさむ。そこで堀口はクロードコードに「Gmailと同じ機能＋自分の情報を踏まえたAI返信＋アカウント切替＋返信パターンの自己学習＋Obsidianを個人情報DBとして参照」を指示してメーラーCメールを自作。ビジネス用と日常用でアカウントごとに口調を学習し、返信するほど自分の言い回しに近づく仕組み。

3. 在庫管理ツール — SaaS課金を置き換える

自社ブランド「ドリップ」のSKU約250種・倉庫2拠点の在庫数・推移・発注タイミングを可視化するツールを自作。月次推移グラフ、商品マスタ入力、レポート出力まで実装。「在庫管理SaaSは月数万円かかるが、これが作れた時点でClaudeのProプランの元は取れている」と評価。SaaSの汎用機能を諦めて自分専用に最適化できることが、自作アプリの真価。

4. Conductor Studio — ハードウェアのソフトも一晩で

堀口開発中の左右分割キーボード「Conductor」のキーマップ／トラックボール感度／コンボ機能をワンクリックで書き換えるカスタマイズアプリを、AIだけで一晩構築。新フォーマットZMKに対応した実装が世になく自力では諦めていたが、相談したらUIまで含めて完成。USB経由でログを取りバグを自動修正までする。「ソフトの世界だけじゃなく物理デバイスの開発速度も爆速化」が衝撃ポイント。

5. YouTube字幕自動化 — Final Cut連携

動画の元ファイルをクロードコードに渡すと文字起こし→Final Cut Proで使えるテロップデータとして出力。GUI上で結合・分割・編集も可能。さらに作った字幕をCodexに渡して学習させ、堀口の話し方・テロップの好みを2ヶ月で吸収し誤字脱字が減少。「もう少し回せばフル自動になる」段階。

6. チップス① Obsidianを外部脳に

Claudeは長期記憶が苦手で「何度言っても忘れる」が、ObsidianをDBとして接続すれば解決。クロード=実行役、Obsidian=外部の脳という分業で、個人情報・指示時の好み・過去のミス傾向まで永続記憶化。「このミスは二度としない」と一度伝えるとObsidianに記録され、以降の全セッションが血肉として積み上がる。

7. チップス② Codex併用で監視役を立てる

クロードコードだけだと考えが偏りミスに気づきにくい。OpenAIのcodexを監視役として「クロードの動きを見て抜け漏れチェック」させる二人体制が効く。さらに同じObsidian外部脳を両者で共有することで、1つのDBを2エージェントが参照する状態に。「最強のチームがMacの中にいる」感覚。

8. これからの時代観 — 「やりたいこと」を持つ人が強い

AIに仕事を奪われる人は確実にいるが、悲観ではなく「使う側に早く回るべき」というメッセージ。一度自分でAIに作らせる経験をすると、外注していた業務が「これAIでいけるな」と判断できるようになる。さらに「何をやりたいか」「夢・趣味・意志」を持つ人ほどAIは強力な武器になる。3Dプリンタの物理出力×AIのソフト出力で「ハードもソフトも手元で作れる」時代に。

💡 ゆりこの活用メモ

① 明日の朝、Cメール思想を自分の「コンテンツ業務メーラー」に応用する ゆりこは クロードコード と Obsidian を既にヘビーユース中。堀口のCメールで効いてるのは「メーラー自体を作る」ことではなく「Obsidianに溜まった自分の文体・関係性データを毎回プロンプトに自動注入する」設計思想。明日の朝、00_🏢 company/secretary/notes/owner-ceo-log.md と feedback_*.md の文体ルールを束ねた email-drafting-context.md を作って、今後の社外返信ドラフトはこれを必ず読んでから書く運用に切り替える。新規アプリ開発不要、ルール1個追加で同じ効果が出る。

② 在庫管理ツール思想で「kemio茶筒・Armillary・LAVANDA」の進捗ダッシュボードを自作する Notion/Asana/Backlog課金より、案件ごとの「いま何が止まってるか」だけ見えるダッシュボードを Claude Code で一晩で作る価値が高い。GW明けのkemio茶筒12案FB待ち・Armillary26AW提案・LAVANDAボンドロシールが並走中で、毎朝「今日どれに触るか」迷う時間がもったいない。30_🧠 context/master-map.md のYAMLをデータソースにして、シンプルなHTML+JSダッシュボードを月内に作る（PORTFOLIO.スキルの延長線で着手可能）。

③ Codex監視役モデルを「CD思考のセカンドオピニオン」に転用する 堀口がCodexにやらせている「クロードのアウトプットの抜け漏れチェック」を、ゆりこはCD（クリエイティブディレクターの地図）の壁打ちに使う。Claude Code＝企画ドラフト生成役、Codex＝「世界的CD視点で見たらこれは弱い／既出／浅い」のレビュアー役で2人体制を組む。kemio茶筒のFB前にこの構成で一回流すと、ご本人提出前に1回追加レビューが入る安全装置になる。動画でも「ミスに気づきにくい」が監視役の主な役割だと明言されている。
