📌 ポイント

1. 前提 — 弱点があることと被害が出たことは別

脆弱性は悪用されると被害につながる仕組みの弱点。誰かに見つかる前に先に見つけて直すのがスキルの役目。見る観点の基礎は、誰が読めるか（権限）、鍵がコードに書かれていないか、追加した部品に既知の弱点がないかの3つ。スキルを使っても冒頭のような流出が全部防げるわけではない。

2. OpenAI（Codexセキュリティ）と GitHub

OpenAIのプラグインは、コード全体を見るスキャン、変更箇所だけ見るディフスキャン、見つかった問題が成り立つか確かめるバリデーションの3スキル。関連コードまで追って権限の抜けを探す。GitHubはシークレットスキャニング（APIキー等）とディペンデンシースキャニング（追加した部品の既知の弱点）の2つで、GitHub自身の検査機能をMCP経由で呼び、結果をエージェントが説明する。MCP接続と認証が必要で、入れただけでは自動点検されず、部品追加時やコミット前に頼む使い方になる。

3. AWS と Anthropic

AWSはAWS Security Agentへの窓口で、設計書レビュー・コード点検・指摘への対応までを一続きで行う。コードをAWS側に送るため、送る範囲の確認とアカウント・権限の準備が必要。Anthropicは、作りながら点検するセキュリティガイダンス、全体や変更箇所を監査するクロードセキュリティ、単発のスラッシュセキュリティレビューの3系統。レビューは書いた側と別の新しい文脈で行い、修正パッチの適用は利用者が決める。

4. Cloudflare（セキュリティオーディット） — 話者が最重要とした1本

画面・API・認証・データなど構成を整理して点検範囲を記録し、複数のエージェントで探索して、別担当が検証する。検証側は問題が起きない理由も探す。候補は確認済み・追加検証・却下の3つに分かれ、確認済みと未確認が後から分かる。Cloudflareで動かすアプリでなくても使え、複数人で作ったウェブアプリの公開前監査に向く。実行を制限できる環境が無い場合は、確かめきれなかった候補が追加検証として残る。
