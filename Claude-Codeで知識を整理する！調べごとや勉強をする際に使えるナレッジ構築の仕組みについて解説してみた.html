🎯 一言要約

Andrej Karpathy が提唱する「Claude Code で自分専用 Wiki を構築する4ステップ（データ収集→コンパイル→Q&A→リント）」を解説。Obsidian × Claude Code で使えば使うほどパーソナライズされるナレッジ管理システムが作れる。

🗺️ 全体像（4ステップフロー） 

flowchart TD
    A[📥 フェーズ1: データ収集\nObsidian Web Clipper で記事・論文・コードを\nraw/ フォルダに蓄積] --> B[⚙️ フェーズ2: コンパイル\n/ingest コマンドで AI が要約・エンティティ抽出・\nグラフ構造化 → wiki/ フォルダに変換]
    B --> C[💬 フェーズ3: Q&A\n/query コマンドで Wiki に質問\n→ 回答 + コンセプトページとして自動保存]
    C --> D[🔧 フェーズ4: リント\n/lint コマンドで整合性チェック・\nリンク切れ・矛盾を検出・修正]
    D --> A

📌 ポイント①：Andrej Karpathy 発信のナレッジ構築思想

OpenAI共同設立者のAndrej Karpathy（アンドレイ・カーパシー）がSNSで「最近のトークン処理の大部分がコードではなく 知識の操作 に費やされている」と投稿し話題に。自分専用Wikiを作ることで、調べたいトピックを深く整理・蓄積できるシステム。コーディング用途に限定されがちな Claude Code を「知識管理エンジン」として使う発想の転換が核心。

📌 ポイント②：Obsidian × Web Clipper = 最強の収集体制

Obsidianは無料の高機能メモアプリで、グラフビューでノード間の関係性を可視化できる。Chrome拡張「Obsidian Web Clipper」を使えばウェブ記事を1クリックで raw/ フォルダに保存可能。100記事・40万語程度であればベクトルデータベース（RAG）不要で、Claude Codeのコンテキスト（最大100万トークン）にそのまま載せてQ&Aできる。

📌 ポイント③：/ingest → エンティティ抽出でグラフが育つ

/ingest コマンドを実行すると、AIが記事を解析して「エンティティ（人物・組織・概念）」を自動抽出。Anthropicや各概念がノードとしてグラフビューに現れ、関連性が可視化される。/query --save で質問するたびに回答がコンセプトページとして wiki/ に保存され、使えば使うほど自分の興味に特化したナレッジが蓄積されていく。

📌 ポイント④：トークン上限・プランへの実用的な注意

Claude Codeの最上位プラン（MAX 20X）なら使い放題に近い運用が可能。Pro/5Xプランでは大量のテキスト処理でトークン上限に当たる可能性があり、その場合はSonnetモデルに切り替えるか notebooklm などの代替ツールを検討。

💡 ゆりこの活用メモ

  1. wiki-ingest / wiki-compileスキルの理論的バックボーンとして活用 — corin の Zettelkasten が “まさにこのシステムを実装している” 状態。このビデオの4ステップは /wiki-ingest（フェーズ1-2）・/wiki-compile（フェーズ2）・/wiki-query（フェーズ3）・/wiki-lint（フェーズ4）に完全対応している。
  2. Obsidian Web Clipper を raw層の収集ツールとして本格活用 — 現在 SNS 経由で LiteratureNote に保存しているが、ブラウザ記事やデザイン参考ページを Web Clipper で直接 Obsidian に取り込む導線を整備するとリサーチ効率が上がる。
  3. クライアントリサーチ（Armillary / kemio等）に専用 Wiki を作る発想 — 案件ごとに「ローフォルダ + wikiフォルダ」を作り /ingest で定期コンパイルすると、担当CDとしての案件知識が自動蓄積される。
