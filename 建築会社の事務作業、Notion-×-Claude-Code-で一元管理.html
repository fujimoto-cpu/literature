📌 ポイント

1. 情報は必ずNotion一箇所に集約する

スプレッドシートやExcelが社内に何個も分散すると情報がバラバラになり、AIに作業を任せる時代になるほど致命的になる。案件・請求・発注・マスター（元請け／協力業者の会社名・住所・電話番号）をすべて同じNotionワークスペースに集め、社員が知りたい情報はNotionを見れば分かる状態を先に作るのが前提。

2. MCPでNotionとClaude Codeを接続する

MCP（AIと外部サービスを繋ぐ標準規格）でNotionを連携すると、Claudeがデータベースを正確に読み取れる。「4月に完工している案件の請求書を作成して」と頼むだけで、案件DBのステータス・取引先を確認し、あらかじめ渡した請求書スキル（マニュアル）とExcelフォーマットを使って請求書を自動生成、Notionの請求DBにも作成履歴を自動で追記してくれる。2件の請求書作成で約3分。

3. PDFはNotion経由でなく直接Claudeに渡す

見積書・仕様書・施工報告書などNotionに添付したPDF自体の中身はClaudeが読み取れない。Notionのデータベースを参照させる自動化と、PDFやGoogleドライブのファイルを直接Claudeに渡す作業指示は使い分けが必要。

4. 日報・タイムカードもNotionフォームで蓄積する

職人にURLだけ渡せば、Notionアカウントが無くてもスマホから現場名・作業日・施工内容・写真を入力でき、即座にNotionデータベースへ反映される。現場ごとの詳細ページにも自動で紐付く。同じ仕組みで社員の出退勤を記録すれば、給与計算までClaudeに任せられる。

5. 請求忘れ・入金漏れをNotion側で自動検知する

完工日を過ぎてもステータスが「請求済み」に変わっていない案件は、毎朝9時にNotion上でメンション通知される。別に入金管理データベースも持ち、支払予定日と実際の入金日を記録して未入金を追跡している。

💡 ゆりこの活用メモ

① 案件DBのプロパティ設計を真似する 「元請け＝取引先」「ステータス」「着工日／完工日」のようにプロパティを揃えておく発想は、KONNEKTの案件ハブmdの 案件: status: client: 設計と同じ思想。請求済み／未請求のようなステータス欄が自分の案件管理に無ければ、まずそこから揃えると同じ自動化が効きやすくなる。

② 「Notionから読めないもの」を先に仕分ける 見積書PDFや仕様書をClaudeがNotion経由で読めない、という制約は自分の業務でも同じ。案件フォルダのファイルを「Notionから参照OKなもの」と「直接渡すもの」に分けて把握しておくと、次にAIへ自動化を頼むときに迷わない。

16:21 この日報っていうのも現場の職人さんに書いてもらってそれを自動的にここに表示させるように僕はしてますあとはこの最後の資料欄ですね資料のところに現場の図面だったり工事の仕様書見積書っていうのをこのデータベースに入れてファイルに落とし込むってこともできますNotionにはデータも入れられるのでPDFだったり何枚かの画像っていうのは全て添付できるので一つの案件に対して紐づいてファイルも工程表も添付できるのでそこら辺が一元管理できるっていう意味ではかなり強いところかなと思ってます

16:57 次に日報ですね今言ったみたいに現場ごとの日報っていうのも職人さんに書いてもらったりしてると思うんですが僕はここに日報のデータベースっていうのも作っていますこれがどういうものかっていうと先ほどと同じようにデータベースで管理しています職人さんから上がってきた日報っていうのは全部ここに追加されていくようになってますその職人さんはどうやって日報を書いてるかっていうとこの日報の入力フォームっていうのがありますここに現場名だったりその作業の日程施工内容担当者の名前だったりあとはまあ場合によっては現場の写真っていうのもこの日報のフォームで入力することができます

17:36 これはパソコンだけじゃなくて携帯スマホからでもできるのでリンクがあるんですが僕はこの日報のリンクを職人さんに渡しておいて職人さんが作業が終わった後にはここに入力してもらうことでその現場の内容が全てここのデータベースに溜まっていくっていう形になりますはい今さっきの日報のURLからこのスマホで開いてみましたURLを職人さんに渡しておけばこんな感じで日報を書くことができます実際に今入力してみるんですがこんな感じで日報を入力してみましたこれで送信を押してみます

18:09 そうするとこのさっきの日本データベースに追加されています現場名の山田亭と作業日で僕の名前と施工内容が全て反される ようになってますこんな感じでこのリンクを渡しておけば職人さんにその日の日報をスマホから書いてもらってそれがすぐこっちに反映されるっていう形になるのでその 職人さんがノーションを使っていなくてもこれは url だけで回答ができるのでかなり便利な機能となってますその日報はどんどんここに溜まっていくんですが例えば この c 様体っていうこの現場の日報をだけを見たいっていう時はC様邸の詳細の中に日報のデータベースを入れています

18:45 このC様邸の現場の日報のみ追加されるという形になっていきます今のNotionフォームで日報をこのNotionにどんどん貯めていくことによって例えば今のそのNotionフォームだけでも便利なんですがこれをさらにこのクロードと組み合わせることで例えば山田様邸の日報をまとめて現場の状況を教えてくださいっていうのもAIにお願いすることでAIが全て教えてくれたりどの作業がどういう順番で進んだのかっていうのも日報に貯めておくことで最後AIに聞けば回答をNotionから読み取ってしてくれるっていう形になります

19:19 今のは日報をNotionフォームでやっていたんですが社員さんがいる会社さんに関してはタイムカードっていうのもNotionのフォームで作ることもできたりします社員さんが出勤した時刻にNotionフォームで打ち込んであげてさらに退勤する時に情報を入れてあげれば社員さんの出勤状況っていうのもどんどんデータベースにたまって最終的に給料を計算するときにこのクロードにお願いして何々さんの給料計算だったりそういったことも自動化できてかなり効率化できるかなと思ってますここからは請求に関してなんですが

19:55 これ建築業界の皆さんよくわかると思うんですが例えば4月に完工した物件があったとして4月末にしっかり請求をすれば例えば月末締めの40日サイトの取引先であれば6月10日に入金するっていうキャッシュフローになるんですがもし4月の末に請求忘れてしまったっていう時はその次の月5月の末に請求扱いになってしまって約1ヶ月後ろ倒しになってしまうっていうことがあったりします僕の会社でも過去に何回かあったんですが請求を忘れてしまうと入金サイクルが遅れるので

20:31 業者さんの支払いだったり資金的に余裕がなくなってしまうっていうのがあります特にこの建築業界っていうのはちょっとこの支払いのサイトが長いのでそういったところで言うと請求っていうのはもう必ず決まった日程にやらなければいけないと思ってますただやっぱりこの人間が請求書を作っていく過程になるのでもちろん忘れてしまうって時もあると思うんですね例えば今回みたいな4月完工でステータスが完工になっている案件があったとしますこの案件に関しては4月末に請求しなければいけないんですがその請求をせずに放置していた場合その場合っていうのは僕は毎日このノーション側からリマインドをしてくれる ような設計をしていますはい例えばさっきのこの4月案件のところでステータスが

21:17 完工になっている物件があったとします 完工になっている物件は4月30日に請求をしてでさらにこのステータスを請求済みにして請求完了という形になるんですがこの 税立つが請求済みではなくて観光のままになって5月1日になったとしますそうするとその5月1日になった瞬間にこのNotionの中で僕にメンションをしてくれてこの案件がまだ請求していませんっていう風に知らせてくれるっていう仕組みを作ってますこんな形で未請求リマインドっていうページを僕は作ってます毎日朝の9時に請求していない物件があったらこのリマインドをしてくれるっていう仕組みを作っているんですが

21:57 このNotion上で通知が来るので観光日を過ぎているのにステータスを請求済みにしていない物件をここでリマインドしてくれるっていう形になってます今のが請求の管理方法になるんですがさらに僕は入金管理のデータベースっていうのも別で作っていますこのデータベースは請求した物件に対して入金確認をしてその入金がされていれば入金済みされていなければそのまま入金待ちっていうステータスに変えているっていう形になりますこれもよくあると思うんですが請求書は出したんですが入金確認をしていなくて

22:31 実際に1年前にやった工事の入金が実はされていなくて後々になって気づくっていうのも結構あったりしますなので僕はこの入金管理のデータベースを使って毎月支払予定日だったり実際に入金された日程だったりっていうのもここでプロパティを作って入力していますこうすることで請求書だけではなくて入金周りもこのデータベースで管理してさらに入金がされていない物件に関しては確認することができたりするのでこういう風に全部お金回りだったり案件回りっていうのも全て

23:04 Notionで管理するようにしてますこんな感じで僕はこのNotionでダッシュボードを作って事務員さんだったり現場の監督さん社長さんもこのダッシュボードを見れば今の現状の会社の状態入金請求管理っていうのも全てこのNotion上で理解することができるっていう仕組みを作ってます僕はこのNotionを有料プランで使っているんですがもちろん無料でもこういうダッシュボードは作ることができますあとは現場の案件のページを例えば職人さんに共有したい時ってあると思うんですが

23:38 その共有の仕方っていうのもかなり簡単にできるようになっていて例えばこのページここに関しては現場の内容しか入れていないので現場の仕様と工程表あとはメモ書きだったりどちらかというとこの現場サイドの職人さんに伝えなきゃいけない内容が記載されているんですがこれを職人さんにすぐ共有することもできますこの共有ってところを押して公開っていう形にするとこのリンクを知っている人に関してはこのリンクからこの ページを見ることができるので職人さんにこの現場の情報を共有するときにもページ の url を送ってあげることで情報を見ることができますやっぱりこのノーションの 一番いいところはこういう感じで自由に

24:20 データベースを使って情報をまとめたり 工程表っていうのも簡単にこのタイムラインのレイアウトで作ることができるので皆さんの会社にあった情報の管理をする ことができる構築することができるっていうのが一番使いやすいっていうのとあとはノーションにすべて情報をまとめておくことで例えばクロードではなくて他の ai に切り替えた時に mcp でノーションに連携してあげることで新しいAIを使い始めた時でもこの自分の会社の情報を全て正確に渡せるっていうのが一番のメリットになっていると思います

24:53 あとはスプレッドシートだったりExcelと違うところは表の中にこういった案件ごとの詳細のページを作ることができるっていうのとファイルも全て添付できるので本当にそのNotionのページの中で全て管理することができるっていうのが一番の魅力かなと思ってますはいいかがだったでしょうかこんな感じで僕はNotionを情報のハブとして会社の情報現場の情報っていうのを一元管理していますさらに今後先ほども言ったんですが今はクロードがかなりAIの中では使いやすくてさらに正確にいろいろ作業を行なしてくれるっていうものになっているんですが

25:30 今後オープンAIだったりジェミニっていう他のAIプラットフォームがクロードよりいい機能を出してきて他のAIに乗り換えるってなった時でもこのノーションに情報をすべて構築しておけばこのクロードだけではなくて他のAIにも簡単に乗り換えることができます今日のまとめに入るんですが建築業の多くの会社さんでいろんなプラットフォームに情報が散在している状況って結構あると思っていて今後AIを使っていくにはいろんな情報をいろんなところに置くんではなくて一箇所のプラットフォーム今回みたいなノーションに置くことで
