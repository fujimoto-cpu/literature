📝 要約

🎯 CodexやClaude CodeなどのAIエージェントに何を読ませ、どこへ成果物を返させるかを「フォルダ設計」の観点で解説。正解は1つではなく、目的別の5つの実例（分割型・LLM Wiki型・Human Layer型・OpenClaw型・秘書型）を、入り口・判断基準・作業中・完成物・記憶という共通の5役割で比較している動画。

🗺️ 全体像

flowchart TD
    A[入り口<br/>依頼・元資料・チケット] --> B[判断基準<br/>CLAUDE.md/agents.md]
    B --> C[作業中の置き場所<br/>ノートブック・リサーチ・プランズ]
    C --> D{人間の確認}
    D --> E[完成物の行き先<br/>アウトボックス・成果物フォルダ]
    E --> F[記憶と保管<br/>アーカイブ・メモリ.md・ログ]

📌 ポイント

1. フォルダ設計に正解は1つじゃない

フォルダ・ディレクトリ設計はAIエージェントにとっての「ハーネス」（周囲の環境）にあたり、動かし方に直結する。ただし絶対の正解は存在せず、目的（開発／知識蓄積／秘書運用）によって必要な箱が変わる。今回は5つの実例を「形をコピーする」のでなく「AIがどこから仕事を始め、何を読み、どこへ成果物を残すか」という視点で見るのがポイント。

2. ボリス・チェルニー氏の分割型（3層構造）

Claude Code開発者の運用方針を元にした型。一番上に薄いルートCLAUDE.mdを置き（全体共通ルールのみ）、コンテンツ・経理などの仕事ごとのフォルダにその領域だけのCLAUDE.mdを置き、さらに.claude内のスキル図に台本作成や請求書確認などの詳しい手順を置く。指示を削るのではなく「読むタイミング」を分けるのが本質。失敗から得た学びも同じ発想で、全業務共通ならルート、領域限定なら該当CLAUDE.md、作業限定ならスキルへ書き足す。

3. アンドレ・カーペシー氏のLLM Wiki型

「資料は増えているのに知識として使える状態にならない」を解決する型。直下にRaw（元資料をアーティクルズ・ペーパーズ・データ・イメージーズ等の種類別フォルダに保存）とWiki（整理済みの概念ページ）、そしてagents.mdを置く。新しい記事はまずRawへ保存→関連するWikiページがあれば追記・無ければ新規作成→index.mdに入口追加→log.mdに更新履歴を記録、という流れ。原文（証拠）と整理済み知識を混ぜないのが核心。

4. Human Layer型（リサーチ→プランズ→人間確認）

「AIが前提を理解しないままいきなり完成物を作り始める」を防ぐ型。共有フォルダに調査結果を置くResearch、実行前の計画を置くPlans、人間への確認事項を置くPRsを用意し、いきなり本番作業に進まない。調査→計画（ここで人間が一度確認）→本番作業→確認依頼、の順に進める。「悪い調査から悪い計画が生まれ、悪い計画から大量の悪い成果物が生まれる」ため、確認を最後だけでなく調査・計画の段階にも挟むのが要点。

5. OpenClaw型と秘書型（役割別ファイル／4フォルダ）

OpenClaw型はSoul.md（姿勢）・Identity.md（名前や役割）・User.md（相手の好み）・Agents.md（仕事の進め方）・Tools.md（使えるもの）・Memory.md（長期記憶）・日付ごとのメモリーファイルに分け、「人格・相手・業務手順・道具・長期記憶・日次記録」を混ぜないことで原因の切り分けをしやすくする。秘書型（今西氏自身の型）はagents.md/sole.mdの下にInbox（依頼受領）・Notebook（作業中メモ）・Outbox（完成物）・Archive（完了保管）を置き、フォルダ移動がそのまま仕事の進行状況を表す。
