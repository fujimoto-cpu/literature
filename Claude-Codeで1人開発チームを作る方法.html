はじめに―インストールして満足していませんか

Claude Codeをインストールして、対話型のコーディング補助として使い始めた。

質問すれば答えてくれるし、コードも書いてくれる。

でも、なんとなく毎回同じ指示を繰り返していて、基本機能だけで止まっている気がする。

もしそう感じているなら、この記事はまさにあなたのためのものです。

Claude Codeにはインストール直後の対話だけでは見えない3つの強力な機能があります。

フックと、カスタムコマンドと、サブエージェントです。

この3つを組み合わせると、1人でも開発チームのような体制を作ることができます。

フックはファイル保存後に自動でリンターを走らせるといった自動実行ルールです。

カスタムコマンドは/deployや/review-prのようなオリジナルの一発指示です。

サブエージェントはコードレビュー専門やテスト専門といった役割特化のAI分担です。

この記事では専門用語をできるだけ使わずに、この3つの機能の仕組みと作り方と組み合わせ方を解説します。

1. 3つの機能の全体像――何がどう違うのか

まず3つの機能の役割を整理します。

フックは特定のタイミングでシェルコマンドやHTTPリクエストを自動実行する仕組みです。

Claudeがファイルを編集した直後にフォーマッターを走らせるBashコマンドを実行する前に危険なコマンドをブロックするといった使い方ができます。

人間が毎回手動で指示する必要がなくなります。

カスタムコマンドはスキルとして/メニューから呼び出せるオリジナルの指示セットです。

現行の推奨は.claude/skills/ディレクトリにSKILL.mdを配置する方法です。

/skill-nameで一発呼び出しできます。

なお既存の.claude/commands/形式も引き続き利用できます。

毎回同じプロンプトを打ち込む手間がなくなります。

サブエージェントは特定の役割に特化した別のClaudeインスタンスです。

メインの会話とは別のコンテキストウィンドウで動き、終わったら結果だけを返してくれます。

1つのAIにすべてを任せるのではなく、役割を分けることで精度が上がります。

2. フック――裏方で自動的に動くルール

2-1. フックとは何か

フックはClaude Codeのライフサイクルの特定のポイントで自動的に実行される処理です。

たとえばClaudeがファイルを編集した直後や、Bashコマンドを実行する直前などのタイミングに紐づけます。

よくある使い方は以下のようなものです。

  • Claudeがファイルを書き込んだあとに自動でコードフォーマッターを実行する
  • rm -rf のような危険なコマンドを実行前にブロックする
  • セッション開始時にプロジェクトの環境変数を自動で読み込む
  • Claudeの応答が完了したあとにテストを自動実行する

2-2. フックの設定場所

一番基本的な設定方法はsettings.jsonにJSONで書く方法です。

加えてskillsやagentsのYAMLフロントマター、pluginsのhooks/hooks.jsonでも定義できます。

settings.jsonの場合は設定場所によってスコープが変わります。

すべてのプロジェクトに適用

~/.claude/settings.json に書きます。

そのプロジェクトだけに適用

.claude/settings.json に書きます。Gitで共有できます。

個人用のプロジェクト設定

.claude/settings.local.json に書きます。

settings.jsonでの基本的な構造はこうなっています。

{

“hooks”: {

“イベント名”: [

{

“matcher”: “対象ツール名”,

“hooks”: [

{

“type”: “command”,

“command”: “実行するコマンド”

}

]

}

]

}

}

skillやagentのfrontmatterで定義する場合は、そのskillやagentがアクティブな間だけフックが動作し、終了時に自動でクリーンアップされます。

最初はsettings.jsonから始めて、慣れてきたらskillやagent側で管理するのがスムーズです。

2-3. よく使うイベント

フックが発火するタイミングはイベントとして定義されています。

初心者が最初に覚えるべき主要なイベントは以下の通りです。

PreToolUse

Claudeがツールを実行する直前に発火します。コマンドの検証やブロックに使います。

PostToolUse

Claudeがツールを実行した直後に発火します。フォーマッターやリンターの自動実行に使います。

Stop

Claudeが応答を完了したときに発火します。テスト自動実行や通知に使います。

SessionStart

セッション開始時に発火します。環境変数の読み込みや開発コンテキストの注入に使います。

UserPromptSubmit

ユーザーがプロンプトを送信したときに発火します。プロンプトの検証や追加コンテキストの注入に使います。

これ以外にもSubagentStartやSubagentStopやFileChangedなど多くのイベントが用意されています。

全一覧は公式ドキュメントを参照してください。

2-4. 実例: ファイル編集後に自動フォーマット

Claudeがファイルを編集または作成したあとにPrettierを自動で走らせる設定です。

{

“hooks”: {

“PostToolUse”: [

{

“matcher”: “Edit|Write”,

“hooks”: [

{

“type”: “command”,

“command”: “npx prettier —write $(jq -r ‘.tool_input.file_path’ < /dev/stdin)”,

“timeout”: 30

}

]

}

]

}

}

matcherにEdit|Writeと書くことで、Claudeがファイルを編集したときと新規作成したときの両方で発火します。

正規表現が使えるので複数のツール名を|で結合できます。

実運用ではフォーマット対象のファイルパスや拡張子を絞った方が安全です。

上記の例ではstdinから受け取ったJSONのfile_pathを使って、変更されたファイルだけを対象にしています。

2-5. 実例: 危険なコマンドのブロック

rm -rfを含むコマンドを実行前にブロックする設定です。

{

“hooks”: {

“PreToolUse”: [

{

“matcher”: “Bash”,

“hooks”: [

{

“type”: “command”,

“command”: ”\“$CLAUDE_PROJECT_DIR\“/.claude/hooks/block-rm.sh”

}

]

}

]

}

}

スクリプトの中身は以下のようになります。

#!/bin/bash

COMMAND=$(jq -r ‘.tool_input.command’)

if echo “$COMMAND” | grep -q ‘rm -rf’; then

echo “危険なコマンドがブロックされました” >&2

exit 2

fi

exit 0

フックのスクリプトは標準入力からJSON形式でツールの情報を受け取ります。

exit 0で実行を許可し、exit 2で実行をブロックします。

exit 2のときはstderrに書いたメッセージがClaudeにフィードバックされます。

2-6. フックの注意点

settings.jsonでフックを設定する場合はJSON形式で書く必要がありますが、Claudeにフック設定を作ってと依頼すれば対話的に生成してくれます。

JSON形式に不慣れでも心配はいりません。

timeoutフィールドで制限時間を設定できます。

commandタイプのデフォルトは600秒です。フォーマッターのように軽い処理なら30秒程度に設定するのが安全です。

フックにはcommandタイプ以外にも、HTTPエンドポイントに送信するhttpタイプ、LLMに判断を委ねるpromptタイプ、ツールを使える専用エージェントに任せるagentタイプがあります。

最初はcommandタイプだけで十分ですが、必要に応じて他のタイプも検討してみてください。

3. カスタムコマンド――オリジナルの一発指示を作る

3-1. カスタムコマンドとは何か

Claude Codeには/compactや/helpのような組み込みコマンドがありますが、これに加えて自分だけのオリジナルコマンドを作ることができます。

現行の推奨はスキルとして.claude/skills/にSKILL.mdを配置する方法です。

/skill-nameで呼び出せるようになります。

なお既存の.claude/commands/形式でもコマンドを定義でき、こちらも引き続き動作します。

同じ名前のスキルとコマンドが存在する場合はスキルが優先されます。

毎回「テストを実行してフォーマットして結果を報告して」と打つ代わりに、/test-and-reportと一言で済ませられます。

3-2. 作り方

フォルダを作ってSKILL.mdを書くだけです。

mkdir -p .claude/skills/test-and-report

SKILL.mdの例です。

---

name: test-and-report

description: テストを実行し結果をMarkdownレポートにまとめる

disable-model-invocation: true

---

手順

1. npm test を実行してテスト結果を取得する

2. テスト結果を以下の形式でMarkdownにまとめる

- 合格したテスト数と失敗したテスト数

- 失敗したテストの一覧とエラー内容

- カバレッジの概要

3. test-report_YYYYMMDD.md として保存する

disable-model-invocation: trueを設定しているので、Claudeが自動的に実行することはなく、ユーザーの/test-and-reportでのみ起動します。

テスト実行のように意図したタイミングだけで動かしたい場合はこの設定が安全です。

3-3. 便利なカスタムコマンド例

プルリクエスト準備

---

name: pr-ready

description: 現在の変更からプルリクエストの説明文を生成する

disable-model-invocation: true

---

手順

1. git diff main を実行して変更差分を取得する

2. 変更内容を分析する

3. 以下の構成でPR説明文を生成する

- タイトル。50文字以内

- 変更概要

- 変更理由

- テスト方法

- レビューポイント

4. pr-description.md として保存する

依存関係チェック

---

name: dep-check

description: プロジェクトの依存関係を分析して問題点を報告する

---

手順

1. package.json または requirements.txt を読み取る

2. 以下の観点で分析する

- 古くなったパッケージ

- セキュリティ上の既知の問題

- 未使用の依存関係の可能性

3. 優先度別に対応策をまとめる

プロジェクト初期化

---

name: setup-project

description: 新規プロジェクトの初期設定を対話的に行う

disable-model-invocation: true

---

手順

1. プロジェクトの種類を確認する。WebアプリかAPIかCLIツールか

2. 選択に応じた初期構成を提案する

3. 承認を得てから以下を実行する

- ディレクトリ構造の作成

- 設定ファイルの生成

- .gitignore の作成

- CLAUDE.md の初期テンプレート作成

3-4. 組み込みスキルも活用する

Claude Codeには最初から使える組み込みスキルもあります。

  • /batch は大規模な変更をコードベース全体に並列で適用するスキル
  • /simplify は最近変更したファイルの品質をレビューして改善するスキル
  • /debug はデバッグログを有効にして問題を調査するスキル
  • /loop はプロンプトを一定間隔で繰り返し実行するスキル

これらは/メニューに表示されるのですぐに試せます。

4. サブエージェント――専門AIに仕事を分担させる

4-1. サブエージェントとは何か

サブエージェントはメインの会話とは別のコンテキストウィンドウで動く専門特化のAIアシスタントです。

それぞれが独自のシステムプロンプトと使えるツールの制限と独立した権限を持っています。

たとえばコードレビュー専門のサブエージェントを作ると、Claudeはコードレビューが必要な場面で自動的にそのサブエージェントに仕事を委譲します。

サブエージェントはメインの会話を汚さずに独立して作業し、結果の要約だけを返してくれます。

4-2. なぜ分担するのか

1つのAIにすべてを任せると、コンテキストウィンドウが膨張して精度が落ちます。

テスト実行のログやコードレビューの詳細な出力はそれだけで大量のトークンを消費します。

サブエージェントに委譲すれば詳細な出力はサブエージェントのコンテキストに留まり、メインの会話には必要な結論だけが戻ってきます。

さらにモデルを使い分けることもできます。

軽い調査にはHaikuを使い、高度な分析にはSonnetを使うといったコスト最適化が可能です。

4-3. 組み込みサブエージェント

Claude Codeには最初から使えるサブエージェントがあります。

Explore

高速で読み取り専用のエージェントで、コードベースの検索や分析に使われます。モデルはHaikuで低コストかつ低レイテンシです。ファイル編集はできません。

Plan

プランモード中にコードベースを調査するエージェントです。メインの会話のモデルを引き継ぎ、読み取り専用で動作します。

general-purpose

探索と実行の両方ができる汎用エージェントで、複雑な複数ステップのタスクに使われます。

Claudeはタスクの内容に応じてこれらを自動的に選択して使います。

4-4. カスタムサブエージェントの作り方

.claude/agents/ディレクトリにMarkdownファイルを配置します。個人用なら~/.claude/agents/に置けばすべてのプロジェクトで使えます。

/agentsコマンドで対話的に作成することもできます。

CLIの—agentsフラグでJSONとして渡すことも可能で、その場合はセッション限りの一時的なサブエージェントになります。

pluginsのagents/ディレクトリに配置して配布することもできます。

コードレビュー専門エージェント

---

name: code-reviewer

description: コード品質とセキュリティと保守性をレビューする専門家。コード変更後に自動で使われる

tools: Read, Grep, Glob, Bash

model: sonnet

---

あなたはシニアコードレビュアーです。

レビュー手順:

1. git diff で最近の変更を確認する

2. 変更されたファイルに集中する

3. 以下の観点でレビューする

- コードの可読性

- 関数や変数の命名

- コードの重複

- エラーハンドリング

- セキュリティリスク

- テストカバレッジ

フィードバックを優先度別に整理する:

- 重大な問題。必ず修正

- 警告。修正を推奨

- 提案。検討を推奨

具体的な修正例を含めること。

toolsフィールドでRead, Grep, Glob, Bashだけを許可しているので、このサブエージェントはファイルの読み取りと検索とBashコマンドはできますが、ファイルの編集や作成はできません。

レビュー専門なので書き込み権限は不要です。

disallowedToolsフィールドを使えば逆のアプローチも可能です。

すべてのツールを継承したうえで特定のツールだけを除外できます。

テスト専門エージェント

---

name: test-runner

description: テスト実行と結果分析の専門家。テストの失敗時やカバレッジ確認時に使う

tools: Read, Bash, Grep, Glob

model: haiku

---

あなたはテスト専門のエンジニアです。

手順:

1. テストスイートを実行する

2. 失敗したテストを分析する

3. 以下の情報をまとめる

- 合格数と失敗数

- 失敗したテストの根本原因

- 修正提案

- カバレッジの状況

modelをhaikuにしているのでコストを抑えつつ高速に実行されます。

テスト結果の分析は比較的定型的な作業なのでHaikuで十分です。

4-5. サブエージェントの呼び出し方

Claudeは自動的にタスクに適したサブエージェントを選んで委譲します。

手動で指定したい場合は@メンションを使います。

@“code-reviewer (agent)” 認証モジュールの変更をレビューして

自然言語で名前を言及するだけでもClaudeは判断してくれます。

code-reviewerサブエージェントを使って最近の変更をレビューして

セッション全体をサブエージェントとして動かすこともできます。

claude —agent code-reviewer

この場合はセッション全体がcode-reviewerの設定で動作します。

プロジェクトのsettings.jsonにagentフィールドを設定すれば、毎回のセッションで自動的にそのエージェントがデフォルトになります。

4-6. フォアグラウンドとバックグラウンド

サブエージェントはフォアグラウンドまたはバックグラウンドで実行できます。

フォアグラウンド

サブエージェントが完了するまでメインの会話がブロックされます。権限の確認や質問がある場合はユーザーに問い合わせが来ます。

バックグラウンド

サブエージェントが裏で動きながらメインの会話を続けられます。Claudeが自動で判断しますが、「バックグラウンドで実行して」と指示することもできます。実行中のタスクにCtrl+Bを押してバックグラウンドに送ることも可能です。

4-7. サブエージェントにフックを組み合わせる

サブエージェントのfrontmatterにhooksを定義すると、そのサブエージェントがアクティブな間だけ動作するフックを設定できます。たとえばBashコマンドの実行前にバリデーションを挟む設定はこのように書けます。

---

name: db-reader

description: 読み取り専用のデータベースクエリを実行する

tools: Bash

hooks:

PreToolUse:

- matcher: “Bash”

hooks:

- type: command

command: “./scripts/validate-readonly-query.sh”

---

このフックはdb-readerサブエージェントの中でだけ動作し、サブエージェントが終了すれば自動で解除されます。settings.jsonに書くグローバルなフックと違い、特定の文脈に限定した安全策を組み込めます。

5. 3つを組み合わせる――1人開発チームの構成例

ここまでの3つの機能を組み合わせると、以下のような自動化された開発フローが実現します。

シナリオ: 機能開発からPR作成まで

  1. 機能実装中にClaudeがファイルを編集するたびに、フックが自動でフォーマッターを実行する。PostToolUseフックです。
  2. 実装が完了したら/test-and-reportでテストを実行し、結果をレポートにまとめる。カスタムコマンドです。
  3. テストが通ったら@“code-reviewer (agent)“でコードレビュー専門のサブエージェントにレビューを依頼する。サブエージェントがメインのコンテキストを汚さずに独立してレビューし、結果だけを返す。
  4. レビューの指摘を反映したら/pr-readyでPR説明文を自動生成する。カスタムコマンドです。

このフロー全体を通じて、危険なコマンドのブロックがPreToolUseフックとしてバックグラウンドで常に働いています。

人間がやることは、実装の方針を指示することと、レビュー結果を確認して判断することと、PRの最終確認をすることです。残りの定型作業はフックとカスタムコマンドとサブエージェントが分担します。

6. 設定ファイルの全体像

3つの機能がどこに設定されるかを整理します。

settings.json

フックを記述するのが基本です。~/.claude/settings.jsonが個人用、.claude/settings.jsonがプロジェクト用、.claude/settings.local.jsonがプロジェクト内の個人用です。ただしskillsやagentsのfrontmatter、pluginsのhooks/hooks.jsonでもフックを定義できます。

.claude/skills/スキル名/SKILL.md

カスタムコマンドを記述します。これが現行の推奨形式です。既存の.claude/commands/形式も引き続き動作します。プロジェクト用は.claude/skills/に配置しGitで共有できます。個人用は~/.claude/skills/に配置します。

.claude/agents/エージェント名.md

サブエージェントを記述します。プロジェクト用は.claude/agents/に配置しGitで共有できます。個人用は~/.claude/agents/に配置します。CLIの—agentsフラグやplugins経由でも定義できます。

すべてテキストファイルの作成と編集だけで完結します。特別なビルドツールやコンパイルは不要です。

7. よくある質問

Q1: フックとカスタムコマンドの違いがわかりません

フックは自動で発火する仕組みです。

ユーザーが何も指示しなくても特定のタイミングで実行されます。

カスタムコマンドは/skill-nameで明示的に呼び出す指示セットです。

毎回必ず実行したい処理はフック、必要なときだけ使いたい処理はカスタムコマンドと使い分けてください。

Q2: サブエージェントとスキルの違いがわかりません

スキルはメインの会話コンテキスト内で動作するルールブックです。

サブエージェントは独立したコンテキストウィンドウで動作する別のAIインスタンスです。

スキルはプロンプトの節約に、サブエージェントはコンテキストの節約と精度向上に向いています。

Q3: プログラミングができなくても使えますか

カスタムコマンドとサブエージェントはMarkdownファイルを書くだけなのでプログラミング不要です。

フックはJSON形式の設定とシェルスクリプトが必要になる場合がありますが、Claudeにフック設定を作ってと依頼すれば対話的に作成してくれます。

Q4: サブエージェントのトークン消費はどうなりますか

サブエージェントは独立したコンテキストウィンドウを持つため、メインの会話とは別にトークンを消費します。

ただしmodelフィールドでhaikuなどの低コストモデルを指定することで抑えられます。

軽い調査にはHaiku、高度な分析にはSonnetと使い分けるのが効率的です。

Q5: Claude Codeはどのプランで使えますか

利用経路は複数あります。

Claude Proは年払い換算で月17ドル、月払いでは20ドルです。

Maxは100ドルのプランと200ドルのプランがあります。

Team standard seatは年払い20ドル、月払い25ドルです。

Enterpriseはseat料金に加えて利用量課金です。

Anthropic ConsoleでのAPIキー利用や、Amazon BedrockやGoogle Vertex AIやMicrosoft Foundry経由でも利用可能です。

最新の料金は公式ページを確認してください。

Q6: .claude/commands/ と .claude/skills/ はどちらを使えばよいですか

現行の推奨は.claude/skills/です。

スキル形式はYAMLフロントマターによる呼び出し制御やサブエージェント実行やフック定義など、コマンド形式にはない機能を備えています。

既存の.claude/commands/も引き続き動作するので、すでにコマンド形式で運用している場合は無理に移行する必要はありません。

同じ名前で両方が存在する場合はスキルが優先されます。

8. まだ不要な人

Claude Code自体をまだ使い始めたばかりの方は、まず通常の対話で基本操作に慣れてください。

毎回同じ指示を繰り返す場面が出てきて初めてカスタムコマンドの価値がわかります。

フックやサブエージェントはその次のステップです。

対話だけで十分に満足している場合や、作業内容が毎回まったく異なる場合も急いで導入する必要はありません。

9. 導入すべきタイミング

以下のサインが出てきたら導入を検討してください。

  • 毎回同じ指示を打っていると感じるとき。まずカスタムコマンドを1つ作ってみてください。
  • ファイル保存後に毎回手動でフォーマットやテストを実行しているとき。フックで自動化できます。
  • 1つのAIに大量の作業を任せて出力の品質が落ちていると感じるとき。サブエージェントで役割を分けることで精度が戻ります。
  • 開発チームが自分1人しかいなくて手が回らないとき。この3つの機能を組み合わせれば1人でもチーム体制を構築できます。

10. クイックスタートチェックリスト

  • Claude Codeがインストール済みであることを確認します。claude —versionで確認できます。
  • まずカスタムコマンドから始めます。最も頻度の高い繰り返し作業を1つ選び、.claude/skills/スキル名/SKILL.mdを作成してください。
  • /skill-nameで実行して出力を確認します。
  • 次にフックを試します。.claude/settings.jsonのhooksセクションにPostToolUseのフォーマッター自動実行を追加してください。
  • 最後にサブエージェントを試します。.claude/agents/にレビュー専門のエージェントを1つ作り、@メンションで呼び出してみてください。
  • 3つが動くようになったらチームメンバーにもGitで共有してください。

AI要約

Claude Codeの3つの隠れた強力機能（フック・カスタムコマンド・サブエージェント）を組み合わせて「1人開発チーム」を構築する方法。フックはファイル保存後のリンター自動実行やBashコマンドのブロックなど裏方の自動実行ルール。カスタムコマンド（現在はskills/推奨）は/deployや/review-prのような繰り返しの指示をワンコマンド化する仕組み。サブエージェントはメインの会話とは別コンテキストで動く専門AI（コードレビュー担当、テスト担当など）で、並列処理により品質チェックとコーディングを同時進行できる。設定ファイルの全体像、導入すべきタイミング、クイックスタートチェックリストまで網羅。
