📝 要約

🎯 Claude Codeデスクトップに追加された「Projects」は、司令塔役のコーディネーターが複数の実行スレッドを並走させ、メモリ・ライブラリ・ルーチンを1プロジェクトに蓄積できる、サブエージェントの上位互換的な機能という解説。

🗺️ 全体像

    B --> C[スレッド1]
    B --> D[スレッド2]
    B --> E[スレッド3]
    C --> F[ライブラリ/メモリに蓄積]
    D --> F
    E --> F

📌 ポイント

1. コーディネーター＋スレッドの構造

人間はコーディネーターとだけ話し、必要に応じて実行用スレッドが自動で立つ。無関係な依頼を1つのチャットに混ぜずに並走でき、進捗は解決済み・作業中で一覧できる。

2. 推論量の設計 — コーディネーターは低め、スレッドは中〜高

コーディネーターは仲介役で動く回数が多くトークンを消費するため、公式でも推論量は低めが推奨。深く考える作業は実行スレッド側に回す。

3. 蓄積される環境（ハーネス）

プロジェクトごとにメモリ・指示・ライブラリ（成果物が自動保存）・ルーチン・GitHub/ローカルフォルダ/Drive/コネクタ接続を持つ。使うほど文脈が溜まる。クラウドとローカルの両方で作業可能。

注意

ローカルのスキルは自動では読めず、.skillのアップロードが必要。トークン消費は大きい（図解テーマ1件で数百万トークン級の例）。ProとMaxプランから順次開放、TeamとEnterpriseは対象外（動画時点）。

💡 ゆりこの活用メモ

① 案件ごとに1プロジェクトで試す 期限のある案件（BIGBANG等）を1プロジェクトにまとめる発想は、案件フォルダ運用と相性が良い。まず1案件だけで消費量を見る。
