📝 要約

🎯 Claude Code・Codex・Notion AIのどれを選ぶかより、「ルール・スキル・開発物・作業記録」の4つをNotion1か所にマスターとして置き、全AIへ自動で配る構造を作るほうが、AIが増えても壊れない。一人会社の実運用の紹介。

📌 ポイント

1. 比較より「同じルールで使える状態」 — AIの優劣は数週間で変わる

「どのAIが一番か」の比較は、モデルが更新されるたびに答えが変わるのでキリがない。大事なのはどのAIを開いても同じルール・同じスキル・同じ情報で動く基盤を作ること。分担は目安程度にし、日常業務や情報整理はNotion AI、台本・記事・ツール構成などの土台作りはClaude Code、実装とClaude Codeの成果物チェックはCodex、という使い分けにしている。

2. 4つのデータを人の組織に置き換える — 新メンバーへのオンボーディングと同じ

共通ルール＝就業規則・行動指針、スキル＝業務マニュアル、開発物＝資産台帳、作業記録＝日報・引き継ぎメモ。AIへの指示も人に指示するのと同じだと考えるとハードルが下がる。

3. ルールとスキルはNotionが正本 — 編集すると各AIに自動反映

ルールのページを編集すると agent.md・claude.md・Notion AIのパーソナル指示すべてに自動連携する。スキルもNotionのスキルDBが正本で、追加・変更がClaude CodeとCodexに自動で渡る。公式のスキルDL機能は手動で漏れやすいので、自動連携の仕組みを自作している。

4. 開発物はフォルダとNotion DBを自動で連動 — 「どこに作ったか分からない」を消す

開発物はDevフォルダ（アーカイブ・クライアント・コンテンツ・ラボ・Notion・ツールの6つ）に集約。本人はフォルダを見ず、連動したNotionのデータベース（ページ内に概要も記載）で確認する。人にもAIにも共有しやすい。

5. 作業記録はタスクページに溜める — 次のAIの文脈になる

タスクDBの各ページに「目的・現状・決定事項・未決定事項・アクションリスト・作業録」を記録。Claude Code・Codex・Notion AIのどれで再開しても同じページを読むので、使うほどAIが仕事に詳しくなる。

6. 3年続けた時間計測をやめた — AIとの並列作業でシングルタスク前提が崩れた

人が実行中のタスクは常に1つのまま、AIと協業中のタスクを並列で複数並べ、同じDBで管理する。AIが返信するときに確認の重さで色を付ける（緑＝軽い確認、赤＝重い確認、作業中は無色）ルールを共通ルールに入れ、並列でも「今どれを見ればいいか」が一目で分かる。

7. 実演 — 依頼するとタスクページ・フォルダ・DBページが自動で立ち上がる

「取引先との契約更新期限を1か月前にSlackで知らせる仕組み」を依頼すると、既存タスクに該当があるか確認→無ければ新規タスクページ作成→ラボフォルダ作成→Notion DBにも同名ページ作成、まで細かい指示なしで連動する。判断が軽い依頼なのでタスクは緑になった。

💡 ゆりこの活用メモ

① 自分の仕組みを4分類で棚卸しする CORINのvaultは、ルール＝.claude/rules/、スキル＝.claude/skills/、作業記録＝タスクMDの実績ログと、すでにこの4つに近い構造になっている。足りないのは「開発物の台帳」と「確認の重さの色分け」。明日の朝、どれが未整備かを4つ並べて1行ずつ埋めてみる。

② 会社向けのAI基盤の設計材料にする 動画の最後で「組織で使うなら共通ルールと権限の設計が別途必要」と次回予告されている。AI推進の社内展開で、何を共通ルールに入れるかの論点出しの素材として次回動画を待つ。
