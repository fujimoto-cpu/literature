97%の人が知らない、Claude CodeとCodexの両方に同じスキルを共有して常に最新に保つ方法

Claude CodeとCodex、結局どっちがいいんですか。 最近、本当によく聞かれます。でも、正直に言うとこの質問自体がずれています。比べている間に、もっと大きな損失がずっと出ているからです。 AIの進化は、ついていくのがしんどいくらい速いです。Claude CodeにFable 5が来たと思ったら、今度はOpenAIからGPT-5.6のSol、Terra、Lunaが出てきました。次々に来て、正直どれを使えばいいのか、そのたびに迷います。 その気持ち、よくわかります。僕自身、Claude CodeとCodexを両方使っていて、毎週のようにどちらかの新しい挙動に振り回されています。 あなたがこの記事を読んでいる頃には、もう別のモデルが出ているかもしれません。でも、だからこそ先に言っておきたいことがあります。 ツールがどれだけ増えても、優劣を比べる前にやることは変わりません。片方に教えたことが、もう片方にきちんと届いているかどうか。 ここが整っていないまま新しいツールを追いかけても、教えたことがバラバラのまま積み上がっていくだけです。それを1回で解決する方法が、この記事でわかります。 後半には、そのまま自分のAGENTS.mdに貼れる参照規則の全文も置いておきます。コピーして貼るだけで、今日から試せる形にしてあります。 この状態のまま「どっちが優秀か」を語っても、比べる土俵にすら立てていません。同じ説明を受けていない2人を並べて、どっちが優秀な部下かと聞いているようなものです。 「あれ、直したはずなのに」の正体 Claude CodeとCodexを両方使っている人なら、この感覚に覚えがあると思います。 「これ、Claude Codeには言ったけど、Codexには言ってないな」 「Codex側で直したはずのルール、Claude Codeではまだ古いままだ」 「さっき直したばかりなのに、また同じ手順で止まっている」 こういう小さなズレが、気づかないうちに積み重なっていきます。同じ内容を2回書く。2回目を書き忘れる。書いたつもりが実は古いままだった。そのたびに、地味に手が止まります。 でも、これは注意力で防げる種類の問題ではありません。原因は気の緩みではなく、運用の設計そのものにあります。設計を直せば、気をつける必要自体がなくなります。 僕の2ヶ月の失敗 正直に言います。 この仕組みに行き着く前、僕は2ヶ月近く、手作業でCLAUDE.mdとAGENTS.mdをそろえる運用を続けていました。 Claude Code側にはCLAUDE.mdという玄関ファイルがあります。Codex側にはAGENTS.mdという同じ役割の玄関ファイルがあります。どちらも、そのAIが起動するたびに読みに行く場所です。 スキルを1つ更新する。CLAUDE.mdを直す。同じ内容をAGENTS.mdにも書き写す。最初のうちは、これで問題なく回っていました。 でも、更新の頻度が上がってくると、書き写す作業が面倒になってきます。「あとでまとめて直そう」と後回しにする。忙しい日は、片方だけ直して満足してしまう。 気づいたのは、Claude Codeに指示した通りの動きをCodexにさせたら、まったく違う挙動が返ってきた瞬間でした。同じルールを入れたはずなのに、片方は新しい手順で動き、もう片方は2ヶ月前の古い手順のまま動いていました。 その瞬間、自分でも笑ってしまいました。効率化のためにAIを使っているはずなのに、いちばん非効率な運用を持ち込んでいたのは自分自身だったからです。その間、僕は自分でも気づかないまま、2つの別人格を運用していたことになります。 なぜ必ずズレるのか 「自動化って最高」とか言いながら、自分の手でルールを2回書いていた時点で、もう自動でも何でもなかった。 冷静に原理から考えると、答えは単純です。正本が2つある時点で、その運用はもう壊れています。 正本というのは「最新の判断が最終的にどこに書いてあるか」という置き場所のことです。 この置き場所が2つある限り、更新のたびに人間が2箇所を直し続けなければいけません。1回でも直し漏れが起きれば、その瞬間からズレが生まれます。 つまり、ズレるのは根性の問題ではなく、時間の問題です。更新の回数を重ねるほど、直し漏れが起きる確率は上がっていきます。 たとえ100回に1回しかミスが起きない運用でも、更新を100回重ねれば、ミスが一度も起きない保証はどこにもありません。これは注意力を上げても解決しません。仕組み自体が、いつか必ずズレる設計になっているからです。 だからこそ「どっちが優秀か」を比べる前に、そもそも同じ説明を受けているかを先に確認する必要があります。同じ正本を読んでいない2つのAIを比べても、出力の差がモデルの実力差なのか、単に伝えた情報量の差なのか、判別できません。 同じ正本を読ませて初めて、対等な比較の土俵に立てます。そこまで整えてしまうと、実は「比べる」という行為自体があまり意味を持たなくなります。同じ情報を読んだ上での差は、優劣ではなく、その時々の作業にどちらが向いているかという実務判断に変わるからです。 解決の型：正本は1つ、玄関は2つ 覚えておいてほしいのはこの一行だけです。「正本は1つ、玄関は2つ」。 やったことはシンプルです。スキルの実体を1箇所だけに置き、CLAUDE.mdとAGENTS.mdの両方から、その1箇所を参照させる。 スキルはコピーして配るものではなく、1箇所に置いて両方に読ませるものです。賢くするのは2つのAIではなく、両方が読む1つの場所です。 実体は.claude/skills/配下に1つだけ。Claude Code側の玄関であるCLAUDE.mdには「詳細はここを見に行け」という参照だけを書きます。Codex側の玄関であるAGENTS.mdにも、同じ場所を指す参照を書きます。 玄関は2つあっていい。でも、その先にある部屋は1つだけです。 どちらの玄関から入っても、同じ部屋に着く。これができれば、更新は1回で済みます。片方を直せば、もう片方も自動的に最新になります。 再現手順 僕が実際にやった手順は次の5つです。 まず、正本の置き場所を1つに決めます。すでに運用しているスキル置き場があるなら、そこを唯一の実体にします。新しく2箇所目を作らないことが大事です。 次に、相手側の玄関ファイルに参照規則を書きます。具体的には、以下のような内容です。無害化のため、内部の固有タスク名は一般化した表現に置き換えています。

参照規則（相手ツールの玄関ファイルに追記する）

スキルの正本ルールスキルの正本は .claude/skills/ 配下に置く。

コピーを作らず、常にこの場所を直接読みに行く。 更新はここでしか行わない。

読み替え規則Claude Code固有の「エージェントに委譲する」という表現は、このツールでは「自分で実行する」に読み替える。専用エージェントが存在しない前提で、同じ手順を自分の手で進める。

実行禁止リスト自動投稿タスクなど、スケジューラ専用に設計された処理は、このファイルを読んでも実行しない。二重投稿・二重処理を防ぐため、実行主体は元のスケジューラに限定する。

新規スキルの置き場とfrontmatter形式新しいスキルを追加する場合も .claude/skills/{スキル名}/SKILL.md に置き、name / description の形式を既存スキルと揃える。形式がそろっていないと、どちらのツールも正しく読み込めない。

3つ目は、「委譲」を「自分で実行」に読み替える規則を明記することです。Claude Code側の運用にはエージェントに任せるという前提がありますが、Codex側にはその前提がありません。読み替え規則がないと、ここで動けなくなります。 4つ目は、自動投稿タスクのようなスケジューラ専用の処理を、相手ツールで実行禁止と明記することです。読むのはよくても、実行は元のスケジューラに限定します。 最後に、新規スキルの置き場とfrontmatter形式を統一する規則も、あわせて明記しておきます。 ハマった3つの場所 ここまで書くと簡単そうに見えますが、実際に組んでみると3つの穴にはまりました。 最初にはまったのは、禁止ルールの巻き添えです。Claude Code側の玄関ファイルには、もともと「本体が直接コンテンツを作ってはいけない、必ず専用の担当に委譲する」という強い禁止ルールがありました。この文言をそのまま参照規則に含めてしまい、Codex側がこの禁止ルールに縛られて身動きが取れなくなりました。 原因は、参照規則と既存ルールの正面衝突です。打ち手は、読み替え規則の中に「この禁止規定はCodex側では対象外とし、委譲は自分で実行に読み替える」という例外注記を1行足すことでした。 次にはまったのは、勝手な実行です。相手ツールが正本を読んだ結果、自動投稿タスクの手順まで見つけて「これも自分がやったほうが早い」と実行してしまい、二重投稿が起きました。 原因は、参照規則が「読め」としか言っておらず、「実行するな」を明示していなかったことです。打ち手は、実行禁止リストを明文化することでした。 3つ目は、僕自身の運用のクセです。相互コピーで揃える運用を2ヶ月続けた結果、更新のたびに片方を直し忘れて別物になっていました。これは冒頭で書いた僕自身の失敗そのものです。原因は正本が2つあることそのものであり、打ち手は正本一元化しかありませんでした。 思わぬ副産物 意外な副産物もありました。運用ログとして育てている教訓欄を、Claude Code側とCodex側で共用にしたことです。 赤入れというのは、僕から「ここ直して」と指摘が入った修正のことです。この赤入れをどちらのツールで受けても、記録先が同じ1箇所になりました。結果、Claude Codeで受けた指摘も、Codexで受けた指摘も、同じ教訓欄に溜まっていきます。どちらのツールで作業していても、次に読むときは両方が同時に賢くなっている状態です。 やらない方がいいこと・検証環境 やらない方がいいことは3つです。 相互コピーで揃えない。手作業で同期する運用は、更新回数が増えるほど必ず壊れます。 正本を2つに分けない。ツールごとに専用の設定を持たせたくなりますが、それは玄関を分けることと、正本を分けることを混同しています。玄関は分けてよくても、正本は分けません。 自動投稿を素通しさせない。実行禁止リストがないまま参照規則だけ渡すと、相手ツールが読める内容をそのまま実行してしまいます。 検証環境も明記しておきます。Claude Codeで使っているモデルはFable 5、Codexのバージョンは0.144.1です。 まとめ 「どっちが優秀か」ではなく、両方に同じことを一度で覚えさせられているかどうか。これが本当に見るべき論点です。 今日やることは2つだけです。1つ目、正本の置き場所を1つに決めること。2つ目、もう片方の玄関ファイルに、その場所を指す参照を1行書くこと。 これができれば、次に何かを直すのは1回だけで済みます。比較は、そのあとでいい話です。 両方使っているけれど、教えたことがバラバラになっている自覚がある方。そういう方には、この記事の運用設計についていつでも相談に乗ります。気になった方はDMでご相談ください。

📝 要約

🎯 Claude CodeとCodexの両方を使うなら、比較より先に「正本は1つ、玄関は2つ」に揃えるべき、という運用設計の記事。

1. 正本が2つあると必ずズレる

CLAUDE.mdとAGENTS.mdを手作業で同期していた筆者は、2ヶ月で片方が古い手順のままになった。ズレは注意力でなく「正本が2か所ある設計」から必然的に生まれる。

解決の型：スキルの実体は .claude/skills/ に1か所だけ置き、CLAUDE.mdとAGENTS.mdの両方からそこを参照させる。

2. 参照規則に入れる4項目

①スキルの正本は .claude/skills/ に置きコピーしない ②Claude固有の「エージェントに委譲」は「自分で実行」に読み替える ③スケジューラ専用の自動投稿タスクは相手ツールでは実行禁止 ④新規スキルの置き場とfrontmatter形式を揃える。

3. ハマった3つの穴

①既存の「委譲必須」禁止ルールが読み替え規則と衝突して動けなくなった（例外注記1行で解消）②相手ツールが自動投稿手順まで実行して二重投稿（実行禁止リストで解消）③相互コピー運用そのもの（正本一元化で解消）。副産物として、赤入れ（修正指示）の教訓欄が両ツール共用になり同時に賢くなる。
