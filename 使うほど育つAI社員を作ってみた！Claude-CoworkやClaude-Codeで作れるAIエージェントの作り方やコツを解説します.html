📝 要約

🎯 Claude CoworkまたはClaude Codeを使って「使えば使うほど育つAI社員（AIエージェント）」を構築する方法を、壁打ちによる要件定義からフォルダ設計・実際の立ち上げまでフルで実演した動画。

🗺️ 全体像

flowchart TD
    A[壁打ちで要件を言語化] -->|ブレインストームスキル| B[設計書を作成]
    B --> C[フォルダ構成を設計]
    C -->|CLAUDE.md + soul.md + スキルズ| D[AI社員を起動]
    D --> E[タスクを依頼]
    E -->|学習ログ自動蓄積| F[次回は賢くなって応答]
    F --> E

📌 ポイント

1. まず壁打ち — 要件が曖昧なままで作り始めない

「何を作りたいか」をAIに5〜10分ひたすら話しかけて要件定義を行う。壁打ちスキル（ブレインストームファシリテーター）を使うことで、作りたいものの方向性が質問形式で絞り込まれていく。曖昧なままでは「何でもできる」がゆえに「どれも中途半端」になる。

2. CLAUDE.md は薄く保つ — 矛盾と肥大化がAIを混乱させる

CLAUDE.mdには「何がどこにあるか」と「最低限の行動原則への参照マップ」だけを書く。1万行書くと矛盾が入り込み、AIが「前向きながら後ろ向け」のような指示で迷子になる。詳細はsoul.md・skills/・memory/などに分散させる。

3. soul.md で人格を固定する — 育てる対象は1人

soul.mdにパーソナリティ・コミュニケーションスタイル・仕事の進め方（例: Done is better than perfect）を書いておく。チャットを新規開くたびにCLAUDE.mdが呼ばれ、そこからsoul.mdを参照するため、毎回同じキャラクターとして動く。

4. 「育つ」仕組みはフックス（Hooks）で作る

Claude Codeのフックス機能を使うと、ツール実行終了時・セッション終了時などのイベントを起点にスクリプトを自動実行できる。「タスク完了後にlearning.mdに学びを書き込む」などを自動化すると、指示しなくても情報が蓄積される。

5. 情報蓄積の質がAI社員の賢さを決める

ログはログで残しつつ、CLAUDE.mdに渡すのはコンパクトにサマライズしたもの。コンテキストウィンドウの爆発を防ぐために「不要な情報を入れない・可能な限りサマライズ」が原則。溜めれば溜めるほどいいわけではなく、質のいい要約を蓄積する。

💡 ゆりこの活用メモ

① CORINのsoul.mdを作り直す 現在のCLAUDE.md（persona/response-style）はそのままに、「仕事の進め方（Done is better than perfect）」「私（ゆりこ）のこと」を1枚のsoul.mdに集約してみる。CLAUDE.mdからの参照パスを追加するだけ。

② hooks設定でタスク完了後のlearning.md自動書き込みを試す 今は手動で「終わったよ」と言ってタスク更新しているが、hooks機能でタスク完了 → 今日の学びを自動追記まで自動化できる。.claude/settings.jsonのhooksセクションに追記する。
