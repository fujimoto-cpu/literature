📝 要約

🎯 AIエージェントに「ループ」を設計することで、人間が逐一プロンプトを打たなくても自律的に作業が進む仕組み（Loop Engineering）の概念・実践手法を解説した動画。

🗺️ 全体像

flowchart TD
    A[人間がゴールを定義] --> B[ゴールコマンド発行]
    B --> C[エージェントが作業実行]
    C --> D[フック起動＋判定モデルで完了チェック]
    D -->|未完了| C
    D -->|完了| E[人間に返却]
    F[外側のループ：トリガー/定期実行] --> B

📌 ポイント

1. Loop Engineering とは何か

人間がプロンプトを逐一打つ代わりに、「トリガー → エージェントが作業 → 完了判定 → 未完了なら再実行」というループをシステムが自動で回す設計手法。Claude Codeの開発者ボリス・チャーニーが「今やっているのはループを書くことだ」と発信したことで注目を集めた。新概念の発明ではなく、AutoGPT・ReActなど従来の自律エージェント試行錯誤の延長・体系化と見るべき。

2. ループの2層構造（内側・外側）

内側のループ：特定タスクが完了するまで繰り返す作業ループ（ゴールコマンドが担う）。実行役エージェントと判定役モデルを分離し、完了条件を満たすまでプロンプトを注入し続ける。外側のループ：定期実行・外部イベント通知などをトリガーに内側のループを起動する仕組み。こちらは設計難度が高く、GithubワークフローやCICD、クラウド実行基盤が必要。

3. ゴールコマンドの実践（Claude Code）

単純にゴールコマンドでループを回す前に、①Grill with Docs で仕様・認識合わせ → ②イシュー切り分け＋ワークツリー並列化 → ③テストケースを自然言語でレビュー → ④TDD（テスト駆動）でループ実装、という前工程が肝心。ループは「速さのアシスト」であり、品質を上げるものではない。ゴール定義が甘いと望む方向から外れて暴走する。

4. 人間の役割の変化

プロンプトを「書く」→ ループを「設計する」へ役割がシフト。重要になるのは①コンテキストとして何を与えるか、②ループ中に生まれた情報をどう保管するか、③成果物と人間の認識ズレをどう防ぐか（テスト・検証の自動化）。ボリス・チャーニーのヒント：権限オートモード・ダイナミックワークフロー・クラウド実行・自己検証手段の付与。

💡 ゆりこの活用メモ

① CORINへの依頼をゴール定義から始める 「〇〇作って」と丸投げするのではなく「完了条件はこれ・テストケースはこれ」まで詰めてからCORINにループを回させる。前工程（仕様詰め・テスト定義）に時間をかけるほどループの品質が上がる。

② 外側のループはClaude Code Scheduled Tasksで近似できる 完全自律の外側ループは難しいが、定期スケジュール実行（scheduled-tasks）で定型業務を近似的に自動化する。メールやSlack通知をトリガーにしたい場合はGitHub Actionsなど外部基盤と組み合わせる発想を持つ。
